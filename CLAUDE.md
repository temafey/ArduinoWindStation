# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Тип проекта

DIY-железка, а не обычная кодовая база. Нет пакетного менеджера, нет тестов. Git с 2026-08-15,
ветка **`main`** (до 2026-08-16 называлась `master`). `origin` →
`git@github.com:temafey/ArduinoWindStation.git`, репозиторий **публичный** — что это значит
для содержимого, см. §Git. Взаимозависимые артефакты в плоском каталоге:

- `esp32_wind_station/esp32_wind_station.ino` — вся прошивка (~1000 строк, один файл, без RTOS)
- `esp32_wind_station/web_content.h` — **автогенерируемый**, руками не править
- `esp32_wind_station/gen_web_header.py` — генератор: `wind-ui/dist` → `web_content.h`
- `esp32_wind_station/secrets.h` — все пароли, **вне git**; шаблон `secrets.example.h`
  в git есть. Без `secrets.h` прошивка не собирается (см. §Секреты)
- `wind-dashboard.jsx` — главный файл дашборда (~2500 строк) **в корне репозитория**,
  уровнем выше `wind-ui/`. `wind-ui/src/App.jsx` — обёртка в пять строк, которая его
  импортирует. При переносе проекта одной папки `wind-ui` не хватит. С 2026-08-18 рядом
  с ним лежат ещё файлы, и это не дробление ради дробления — у каждого своя причина
  (список неполный, здесь только то, что чаще всего ищут):
  - `ui-kit.js` — палитра, шрифты, функции свечения и полярная геометрия. Вынесены, когда
    появился второй потребитель: две копии палитры расходятся всегда. Шрифты идут через
    CSS-переменные `--ui-sans`/`--ui-mono`, потому что гарнитура стала настройкой, а
    оформление здесь инлайновое — протаскивать её пропсами через полсотни компонентов было
    бы адом
  - `wind-map.jsx` — карта мира: своя проекция Меркатора, слои предупреждений NWS, донесений
    SPC, прогноза конвекции, отражаемости, суперклеточного экрана, городов и архива.
    Отражаемость — мировая тайловая мозаика RainViewer, а не растр NOAA на США: слой,
    который кончался на канадской границе, читался как поломка. Суперклеточный экран
    считается на месте из CAPE и векторного сдвига Open-Meteo по видимому куску карты
    (24 × 15 узлов — больше не влезает в строку адреса, сервер отвечает 414). Оба слоя
    по умолчанию пиксельные: клетка данных рисуется клеткой, а не сглаживается, — и оба
    переключаются тумблерами в «Основных» настройках (`pixelRadar`, `pixelCells`).
    Смерч рисуется воронкой с вихрем обломков, а направление — расширяющимся конусом
    неопределённости из сегмента TML, и только там, где служба сама указала движение.
    Колесо мыши слушается вручную через `addEventListener(..., { passive: false })`:
    React вешает `wheel` на корень пассивным, и с атрибутом `onWheel` карта
    приближалась вместе с уезжающей из-под курсора страницей
  - `wind-live.jsx` — «эфир»: живые снимки GOES-19/18 и радарная петля NWS. Кадры
    качаются через `fetch` с чтением потока, поэтому видно настоящий ход приёма в
    процентах и мегабайтах; где у хоста нет CORS, остаётся обычный `<img>` без полосы
  - `wind-tutor.jsx` — восьмибитный подсказчик и знак станции (киви в разрезе)
  - `wind-permissions.jsx` — панель разрешений браузера и объяснение, почему по HTTP их нет
  - `wind-themes.js` — темы оформления. Тема меняет не цвета, а материал панели, и делает
    это через переменные `--pnl-line` / `--pnl-bg` / `--pnl-shadow` / `--pnl-blur` /
    `--pnl-corner`. Иначе никак: оформление инлайновое, а инлайновый стиль сильнее любого
    правила — тема до панели просто не дотянулась бы. Каждая тема ещё выставляет
    «спутников» (материал подложки, скругление, свечение) через `apply(settings)`,
    но не затирает чужую картинку в сцене. Два места, где тема выходит за
    переменные: `glassRich()` решает, нужно ли вообще размытие под стеклом
    (под гладким градиентом размывать нечего — дашборд вешает класс `gl-deep`
    только когда под панелью картинка или зерно), а темы с полем `veil`
    получают плёнку в три слоя поверх всего экрана
  - `wind-switch.jsx` — тумблер для настроек с двумя значениями плюс `SwitchGlyph` —
    его вид без обработчиков, для случаев, когда переключателем работает вся кнопка
    целиком (слой карты, режим светодиодов): вложенная кнопка была бы недопустимой
    разметкой. Стили отдаются строкой `SWITCH_CSS` и вклеиваются в общий `<style>`
  - `storm-archive.js` — справочный архив смерчей с рейтингами EF по обследованиям NWS/NCEI
  - `world-rings.js` — **автогенерированные** контуры суши (Natural Earth 110m, 84 кольца,
    8.8 КБ gzip). Руками не править
  - `world-cities.js` — короткий список городов для подписей на карте
- `wind-ui/` — Vite-обвязка дашборда (React 19 + Vite 8, чистый JS, без TypeScript)
- `wind-station-assembly.md` — руководство по сборке (BOM, разводка, распиновка, диагностика)
- `FIRMWARE.md` — разбор прошивки: архитектура, тайминги, калибровки, ловушки отладки
- `FLASHING.md` — заливка, вход в download mode, разбор ошибок
- `PUBLISHING.md` — публичная копия дашборда на статическом хостинге
- `A7670E-DRIVERS.md` — драйверы и первый запуск платы 4G/GPS на Windows; рядом
  `drivers/` (вендорский архив, `install-drivers.ps1`, `at.ps1` для AT-сеансов).
  Модуля в станции пока нет, это задача `tasks/10-a7670e-4g-gps.md`

Документация, строки UI, Serial-логи — по-русски. Комментарии в `.ino` — по-английски.
Имя папки скетча обязано совпадать с именем `.ino`, иначе arduino-cli скажет
«в скетче отсутствует основной файл».

## История версий

Версия от 2026-08-13 (форк `WindCatcher`, собран на другой машине) перенесена сюда 2026-08-15
и стала основной. Предыдущая версия — клиент домашней WiFi-сети с пулом сетей в NVS — лежит
целиком в `archive/firmware-v2-multiwifi-2026-08-02/`. Каталог остаётся на месте: он старше
первого коммита (2026-08-15), поэтому история git до него не достаёт и откат этих версий —
по-прежнему только копированием файлов из `archive/`.

**Что залито на плату сейчас.** С 2026-08-18 на чипе актуальная сборка из этого дерева:
AP+STA, AT-консоль модема, `/api/site`, защита эндпоинтов записи и текущий дашборд.
Признак в Serial — строка телеметрии с `mV`/`zero`/`loopMax` и сообщения `Uplink … joined`.
Проверять, что именно на плате, надёжнее всего по `/api/wifi`: наличие `uplinkSsid`
означает сборку не старее 08-15, а `/api/site` — не старее 08-18.

## Архитектура — как части связаны

Правка любого из трёх пластов (прошивка / дашборд / документ сборки) без правки остальных
ломает систему. **Редактировать как набор, а не по отдельности.**

### Сеть: точка доступа всегда, домашняя сеть — вдобавок

Точка доступа безусловна: поднимается на старте, и **ни одна строка прошивки её не гасит**.
Это главный урок старого станционного режима — плата держала пул сетей в NVS, на старте
входила в сильнейшую, и `softAPdisconnect()` убивал AP через ~15 с после включения; станция
пропадала с телефона. Тот режим не вернулся и не вернётся.

С 2026-08-15 добавлен **AP+STA** (`WIFI_AP_STA`): плата одновременно раздаёт свою сеть и
входит в домашнюю. Разница со старым режимом принципиальная — подключение к сети делается
**в дополнение** к точке доступа, а не вместо неё, и провал подключения не стоит ничего,
кроме самого аплинка. Настраиваемая часть не вернулась: пул сетей в NVS,
`/api/wifi?add|del|connect`, перескан раз в 30 с и трёхминутный фолбэк-AP по-прежнему мертвы,
а аплинк — константа в `.ino`, а не форма на странице.

- SSID `WindStation`, **WPA2, пароль — `SECRET_AP_PASSWORD` в `secrets.h`** (ESP32 требует
  8..63 символа; короче — `softAP()` молча поднимет открытую сеть), не более 4 клиентов
- Адрес `http://MyWindProbeBETA.org` — резолвится собственным DNS-сервером платы (catch-all
  на этот адрес), поэтому работает и на Android, где `.local` ненадёжен. `192.168.4.1` работает
  всегда. Captive-portal анонсируется через DHCP option 114
- mDNS-метка `mywindprobebeta` → `mywindprobebeta.local`, под этим же именем плата видна
  в списке сетевых портов Arduino IDE. Пароль OTA — `SECRET_OTA_PASSWORD` в `secrets.h`
- Домен на нас не зарегистрирован. Пока устройство подключено к станции, настоящий сайт на
  этом домене для него будет затенён — но у AP всё равно нет аплинка

**Аплинк** — `SECRET_HAS_HOME_NETWORK` и `SECRET_HOME_NETWORKS` в `esp32_wind_station/secrets.h`
(**файл вне git**, см. раздел «Секреты» ниже). Флаг `0` = чистая точка доступа, и тогда кода
ретраев не существует вовсе (мачта, дача, поле).

- **Список, а не одна сеть.** `SECRET_HOME_NETWORKS` — пары `{ssid, password}`,
  порядок = приоритет. Добавить сеть = дописать строку в `secrets.h` и перезалить;
  форм и NVS для этого нет и не будет. Это один макрос на несколько строк: каждая строка,
  кроме последней, кончается `\`, а комментарии внутри — **только `/* */`**, потому что `//`
  съел бы остаток склеенной строки вместе со следующими сетями
- **Только 2.4 ГГц.** У ESP32 нет радио на 5 ГГц, поэтому половина `-5G` двухдиапазонного
  роутера для него невидима — сколько её ни вписывай
- Радио одно, канал общий: AP стартует на канале 1, а когда аплинк входит в роутер на другом
  канале, **точка уезжает следом**. Клиенты AP при этом один раз отваливаются и
  переподключаются. На однорадийном чипе это неизбежно — потому поиск аплинка и запускается
  последним делом в `setup()`. Вдали от дома ассоциации не происходит вообще, и канал 1
  остаётся неподвижным
- **Сначала скан, потом ассоциация** (с 2026-08-23). До этого список обходился вслепую:
  `WiFi.begin()` на каждое имя по очереди, каждому `STA_ASSOC_MS` = 12 с на молчание.
  Шесть сетей = **72 с метаний по каналам после каждого включения** — и ровно в это окно
  человек в поле пытается подключить телефон. Ассоциация телефона такого не переживает,
  ноутбук ретраит дольше и просачивается: отсюда симптом «ноутбук подключается, телефон
  нет». Теперь один асинхронный скан (`STA_SCAN_MS_PER_CHAN` = 120 мс × 13 каналов ≈ 1.6 с)
  отвечает сразу за весь список, и если ни одной знакомой сети в эфире нет — ни одного
  `WiFi.begin()` не делается. Из найденных берётся **самая ранняя в списке**, не самая
  громкая: порядок в `SECRET_HOME_NETWORKS` — это приоритет. Канал и BSSID передаются
  в `begin()`, чтобы ассоциация шла на одном канале, а не искала имя по всем
- **Молчание, пока кто-то на точке.** Если прошлый скан не нашёл ничего своего
  (`staNoneInRange`) и на AP есть клиент — плата не сканирует вовсе. Дешёвый скан всё равно
  оставляет 1.6 с дыру посреди чужого сеанса, а в поле искать нечего. Проверит снова,
  когда клиент уйдёт
- Попытка бросается сразу по `WL_NO_SSID_AVAIL`/`WL_CONNECT_FAILED`, не досиживая 12 с,
  и завершается `WiFi.disconnect(false, false)` — иначе драйвер продолжает ретраить сам,
  уводя радио с канала AP. Это единственный `disconnect()` вне `setup()`, и точки он
  не касается
- Пауза с удвоением 30 с → 10 мин (`STA_RETRY_MIN_MS`/`STA_RETRY_MAX_MS`) — между поисками.
  `WiFi.setAutoReconnect(false)`, чтобы ретраями рулило одно место
- `serviceUplink()` вызывается из `loop()` каждый проход и **никогда не блокирует** —
  `WiFi.begin()` только запускает ассоциацию, результат читается на следующих проходах.
  Блокирующий `wifiMulti.run()` на 30 с из старого режима — ровно то, чего здесь нет
- На старте прошивка стирает креды STA из NVS (`WiFi.disconnect(true, true)` до
  `persistent(false)`): аплинком должно быть то, что написано в исходнике, а не остатки
  от какой-то прошлой сборки — раздел `nvs` не переписывается при OTA и живёт вечно
- IP в домашней сети виден в Serial при подключении, в `/api/data` (`staIp`) и в `/api/wifi`
  (`uplinkIp`). Какая именно сеть из списка отозвалась — `staSsid`/`uplinkSsid` (берётся
  из драйвера, не из констант), весь список имён — `uplinkKnown` в `/api/wifi`
- Пароли аплинка — в `secrets.h`, не в `.ino` и не в git (было наоборот до 2026-08-16,
  историю почистили). В скомпилированный `.bin` они всё равно попадают открытым текстом:
  прошивка не пишет NVS, деть их некуда — но это уже вопрос к тому, кому отдаётся бинарник

### Секреты: `esp32_wind_station/secrets.h`

Единственное место, где лежат пароли. **Файл в `.gitignore`**, в git — только шаблон
`secrets.example.h`. На свежем клоне: `copy secrets.example.h secrets.h` и вписать сети.

- Без `secrets.h` скетч **не собирается** — в `.ino` стоит `#error` под `__has_include`.
  Это намеренно: молчаливый фолбэк дал бы плату, поднявшую **открытую** сеть, а такую
  ошибку замечают только когда на ней уже кто-то сидит
- Макросы: `SECRET_AP_PASSWORD` (WPA2 точки, 8..63 символа — короче, и `softAP()`
  молча откроет сеть), `SECRET_OTA_PASSWORD`, `SECRET_HAS_HOME_NETWORK` +
  `SECRET_HOME_NETWORKS`, `SECRET_STATION_LAT`/`LON`/`ALT_M` (координаты мачты — полная
  точность это домашний адрес, потому они тоже здесь, а не в скетче)
- Пароли аплинка вычищены из истории git (`filter-repo`, 2026-08-16). Пароли **самого
  устройства** — точки и OTA — перед публикацией **сменили**: их старые значения лежали
  ещё и внутри gzip в `web_content.h` и внутри `WindStation-kit.zip`, а это бинарные блобы,
  подстановкой не берутся. Смена и была фиксом; плейнтекст потом всё равно вычистили
  третьим проходом. В документации теперь везде имя макроса, а не значение — так и держать

### Контракт HTTP API (прошивка ↔ дашборд)

Порт 80, у всех ответов `Access-Control-Allow-Origin: *`. Основной канал данных — SSE
(`/api/stream`, 20 Гц); дашборд дополнительно опрашивает `/api/data` как heartbeat и фолбэк —
раз в 5 с пока поток жив, раз в 1 с иначе. **Не чаще 1 Гц**: WebServer всегда закрывает
соединение, а lwIP держит 16 TCP PCB по 60 с в TIME_WAIT каждый.

- `GET /api/data` — JSON: `speed`, `direction`, `dirPresent`, `gust`, `speedMv`, `speedZeroMv`,
  `speedSpreadMv`, `speedMax`, `ledGreen`, `ledYellow`, `ledRed`, `ledWifi`, `ledAuto`,
  `battery`, `batteryPercent`, `batteryPresent`, `chargeState`, `powerSource`, `wifiRssi`,
  `adcError`, `staSsid`, `staConnected`, `staIp`, `hostname`, `uptime`. Дашборд кладёт сырой
  ответ прямо в состояние `data` — переименования и смена типов только синхронно с ним.
  - `speed` и `gust` — **два знака после запятой**: при одном квантование в 0.1 м/с было
    грубее собственного шума датчика после усреднения по 32 отсчётам
  - `speedMv` / `speedZeroMv` / `speedSpreadMv` — диагностика, дашборд их игнорирует: сырые
    усреднённые мВ на пине скорости, действующая точка нуля и разброс одной пачки отсчётов
    (по нему видно наводку). Позволяет проверить пол АЦП без USB-кабеля
  - `hostname` теперь отдаёт `MyWindProbeBETA.org` — адрес для человека, а не mDNS-метку
  - четыре поля `led*` — строки режима `off` / `on` / `blink` (дашборд ещё нормализует
    булевы из прошивок до появления blink); `ledAuto` остаётся булевым
  - `chargeState` — `absent` / `charging` / `full` / `discharging`, `powerSource` —
    `external` / `battery`. Оба берутся со статусных линий TP4056 на GPIO13/19, а не
    угадываются по напряжению — см. раздел CHRG/STDBY в документе сборки
  - `staSsid` / `staConnected` / `staIp` — аплинк (добавлены 2026-08-15, дашборд их пока
    игнорирует). `staIp` — единственный способ узнать адрес платы в домашней сети,
    не открывая роутер или Serial. `staSsid` — какая сеть из списка отозвалась (`null`,
    пока связи нет). При `HAS_HOME_NETWORK 0` — `null` / `false` / `null`
  - `wifiRssi` — сигнал того канала, через который скорее всего смотрят: если к AP кто-то
    подключён, это лучший из клиентов; если AP пуста, а аплинк есть — `WiFi.RSSI()` домашней
    сети. `0`, когда нет ни того ни другого
  - **опциональные датчики** (контракт согласован 2026-08-18, в прошивке их пока нет):
    `tempC`/`tempPresent`, `humidity`/`humidityPresent`, `pressureHpa`/`pressurePresent`,
    `rainMm`/`rainPresent`, `lux`/`luxPresent`, `uvIndex`/`uvPresent`. Дашборд уже умеет
    их показывать и рисует карточку **только** при истинном флаге присутствия — по тому
    же правилу, что направление и батарея. Флаг обязателен: ноль вместо отсутствующего
    датчика это худшее, что может сделать метеостанция, потому что 0 °C — это мороз,
    а не «термометра нет». Значения всегда в СИ, пересчёт делает дашборд. Точка росы
    (формула Магнуса) и «ощущается как» (формула NWS, только в холод при ощутимом ветре)
    считаются на клиенте и датчиками не являются — при выходе за область определения
    их просто нет
- `GET /api/stream` — Server-Sent Events, тот же JSON кадрами `data: {...}\n\n` каждые 50 мс.
  Подписчик один: новое подключение вытесняет предыдущее. Работает потому, что сокет
  `NetworkClient` у WebServer — `shared_ptr`, и прошивка держит копию после конца запроса
- `GET /api/led?auto=true|false` и `?green=…&yellow=…&red=…&wifi=…` со значениями
  `off` / `on` / `blink` (старые `true`/`false` ещё разбираются); действует только при `auto=false`
- `GET /api/gust` — сбросить пиковый порыв
- `GET /api/zero` — калибровка нуля на месте, с неподвижными чашками: без аргументов показывает
  действующее значение и текущий отсчёт, `?set` принимает текущий, `?set=374.0` — явный,
  `?reset` возвращает к константе. **Только в RAM**: прошивка никогда не пишет NVS, поэтому
  ответ отдаёт готовую строку константы для вставки в исходник
- `GET /api/wifi` — только чтение: `{mode:"ap", apOnly:true, current, ip, clients, host,
  uplinkSsid, uplinkConnected, uplinkIp, uplinkRssi, uplinkKnown, max:0, nets:[]}`.
  `uplinkKnown` — имена всех сетей из `homeNetworks[]` (пароли не отдаются никогда, ни здесь,
  ни где-либо ещё): по нему видно, что эта сборка вообще будет пробовать. Настраивать по-прежнему
  нечего, но эндпоинт оставлен — встроенный дашборд его опрашивает. **`apOnly` остаётся
  `true` и при живом аплинке**: дашборд читает этот флаг как «настроек сети нет», что правда,
  а `false` заставил бы старый вшитый UI показать редактор поверх удалённых эндпоинтов
- `GET /api/site` — где стоит станция: `{lat, lon, altM, host}` из `SECRET_STATION_*`
  в `secrets.h`. Появился 2026-08-18 и закрывает конкретную дыру: на копии, отданной
  платой по обычному HTTP, браузер **отказывается** сообщать место смотрящего
  (геолокация только для защищённого контекста), поэтому место самой станции —
  единственная реальная точка, на которую карте можно опереться. Полная точность
  здесь намеренна: это своё устройство в своей сети, а правило округления до трёх
  знаков — про то, что уходит в git и в документацию, а не про то, что плата говорит
  своему же дашборду. `0/0` означает «не настроено», и дашборд читает это именно так,
  а не как точку в Гвинейском заливе
- **Защита эндпоинтов записи.** `/api/led`, `/api/gust`, `/api/zero` и `/api/at` начинаются
  с `crossSiteWrite()`. Угроза не в соседе по локальной сети, а в **любой странице,
  уже открытой в том же браузере**: API принимает обычные GET-ы, поэтому произвольный
  сайт может отправить запрос на `192.168.4.1/api/led`, и браузер его отправит.
  Wildcard `Access-Control-Allow-Origin` прячет от чужого скрипта только **ответ** —
  запрос всё равно доходит и срабатывает, а через `/api/at` он мог бы отправить SMS.
  Собственный GET дашборда заголовка `Origin` не несёт вовсе, поэтому «Origin есть
  и он не наш» — это ровно межсайтовый случай и ничего больше; такой запрос получает
  403. `localhost` в белом списке намеренно: это `npm run dev`, нацеленный на живую
  плату. Работает только вместе с `server.collectHeaders({"Origin"})` — WebServer
  хранит лишь те заголовки, о которых его попросили, и без этого вызова guard молча
  пропускает всё
- **Заголовки безопасности** на встроенных страницах (`sendPageSecurity()`):
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` и CSP.
  Секретным контекстом это страницу **не делает** — это умеет только настоящий TLS,
  а сертификат доверенного центра на приватный IP не выдаст никто; но это та часть,
  которая бесплатна. `Permissions-Policy` явно **разрешает** геолокацию своему
  происхождению, чтобы единственным препятствием остался сам браузер. В CSP
  `img-src`/`connect-src` пускают `https:` целиком: карта мира тянет предупреждения
  с `api.weather.gov` и растры с NOAA, а эти хосты не наши, чтобы их прибивать.
  `'unsafe-inline'` для стилей — потому что весь дашборд свёрстан инлайн-стилями
- `GET`/`POST` `/api/at` — AT-консоль модема A7670E, только при `HAS_MODEM 1`. Появилась
  потому, что модуль сидит на макетке наклейкой вниз и его micro-USB недоступен. Ответ —
  `text/plain`: эхо команды, сырые байты модема, трейлер `-- rx=… total=… waited=…мс`.
  `?cmd=AT%2BCSQ` — из браузера (**`+` обязан быть `%2B`**, WebServer декодирует `+` как
  пробел); `POST` с `Content-Type: text/plain` и командой в теле — из терминала без
  экранирования (с дефолтным для curl form-типом `+` снова станет пробелом); без
  аргументов — забрать URC и поток NMEA. `&wait=N` (0…3000, по умолчанию 500) — ожидание
  ответа, **оно блокирует `loop()`** и видно в `loopMax`; выход досрочный по финальному
  коду. Долгие команды — с `wait=0`, ответ следующим запросом. `total` — счётчик всех
  принятых байтов: ноль при живом эхе означает провода или скорость, а не прошивку.
  `&pins=RX,TX` (только 25/26/27) и `&baud=N` переоткрывают UART2 **на лету, без
  перезаливки** — какой из двух проводов сел на какой пин, иначе стоит USB-сессии
  с кнопками. Только в RAM, как `/api/zero`: рабочее сочетание переносить в константы.
  **Единственный эндпоинт без `Access-Control-Allow-Origin`** — здесь команда может
  отправить SMS, и чужая вкладка не должна суметь прочитать IMEI/ICCID
- `GET /` и хешированные `/assets/*` — встроенный дашборд (gzip из PROGMEM,
  `Content-Encoding: gzip`), маршруты регистрируются из `web_content.h`. Только GET, на HEAD 404

Дашборд, отданный самой платой (порт 80, не localhost), использует `window.location.host`
и игнорирует localStorage. Константа `PUBLIC_COPY` в `wind-dashboard.jsx` отличает копию на
хостинге (HTTPS) от копии на плате (HTTP) и включает демо-режим — один бандл обслуживает оба
места, отдельной сборки для публикации нет.

### Карта GPIO (прошивка ↔ документ сборки ↔ железо)

Таблица распиновки в `wind-station-assembly.md` обязана совпадать с макросами `PIN_*`.

- **Аналоговые входы (только ADC1)**: GPIO34 = скорость, GPIO35 = направление (не подключён,
  см. `HAS_DIRECTION`), GPIO32 = напряжение батареи
- **Светодиоды**: GPIO17 = зелёный (батарея >60%), GPIO16 = жёлтый (ветер >5 м/с ИЛИ батарея
  30–60%), GPIO4 = красный (ветер >15 м/с ИЛИ батарея 10–30%, мигает при <10%),
  GPIO5 = WiFi (**горит, когда станция кому-то доступна — есть клиент на точке ИЛИ живой
  аплинк; мигает, только когда ни того ни другого**), GPIO18 = ошибка. Зелёных ламп две,
  и их путают: ровный свет GPIO5 — это сеть, а не заряд. Схема v4 перенесла светодиоды на нижний
  ряд пинов (колонки макетки 5–9), резисторы 220 Ω теперь на плате; было 26/27/14/25/33
- **UART модема 4G/GPS** (`HAS_MODEM 1`): GPIO26 = TX → кол. 37 макетки (буква `R`, RXD
  модема), GPIO25 = RX ← кол. 38 (буква `T`, TXD). Буквы через линк намеренно не
  совпадают. **Не 27/26, как рисовалось в v6:** косичка встала на один пин мимо, а
  переставить её нельзя без разборки — прошивка пошла за медью. GPIO27 свободен, затвор
  P-FET перепланирован на **GPIO33**. Оба пина — ADC2, и это допустимо (UART, не
  аналоговое чтение). Главное: **`Serial2` по умолчанию сидит на GPIO16/17 — это жёлтый
  и зелёный светодиоды**, поэтому пины передаются в `Serial2.begin()` явно
- **Статус TP4056**, открытый сток, `INPUT_PULLUP`, активный уровень LOW: GPIO13 = CHRG,
  GPIO19 = STDBY. Выбраны потому, что ни один не strapping — линия с открытым стоком,
  прижатая к земле в момент включения на GPIO0/2/12/15, поменяла бы режим загрузки
- GPIO4 — пин ADC2, используется как обычный цифровой выход: это можно, конфликт ADC2/WiFi
  касается только аналогового чтения. GPIO5 — strapping: светодиод на землю через 220 Ω
  лишь коротко мигнёт при включении

**Никогда не переносить аналоговые входы на ADC2 (GPIO 0, 2, 4, 12–15, 25–27)** — ADC2
недоступен, пока работает радио.

### Математика сигнала завязана на номиналы резисторов

Константы прошивки и номиналы в BOM обязаны совпадать.

- Делитель датчика: **10 кΩ + 5 кΩ последовательно (= 15 кΩ) сверху + 10 кΩ снизу** →
  `Vsensor = Vadc × 2.5` (`SIGNAL_DIVIDER_RATIO`). В наборе нет 15 кΩ, поэтому верхнее плечо
  собрано из двух; отношение то же. Почему не наоборот: АЦП ESP32 на 11 dB линеен только
  150 мВ … 2.45 В, а большее плечо снизу дало бы 3.0 В на полной шкале и занижало бы
  скорости выше 49 м/с на 5–15%
- Делитель батареи: 100 кΩ + 100 кΩ → `Vbat = Vadc × 2.0` (`BATTERY_DIVIDER_RATIO`).
  Тапится провод холдера, а не TP_B+: TP4056 подпитывает TP_B+ от USB и подделывает батарею
- Датчик **новый**: 0–30 м/с, только скорость. `SPEED_MAX = 30.0` — оставленные там 60
  от старого датчика удваивают каждое показание. `HAS_DIRECTION 0`, GPIO35 висит в воздухе
- Питание: диодное ИЛИ на **двух 1N5819** + **двух Mini Boost** (HW-085/TMF002 на MT3608;
  №1 = 12 В для датчика, №2 = 5 В от батареи). Шина ~4.7 В независимо от источника.
  Второй буст нужен потому, что падение на AMS1117 — 0.8–1.25 В, а не 0.3 В: без него
  один диод от батареи оставил бы шину на 3.4 В и ESP32 ловил бы brownout на передаче

Смена физических резисторов без правки константы даёт молча неверные показания. В одной из
прошлых версий баг вида `(raw/4095) × 1.515 × 60` завышал скорость в 1.5 раза — при правке
математики АЦП сохранять `analogReadMilliVolts()` (применяет калибровку из eFuse), а не
сырой `analogRead()`.

### Порог АЦП — это гейт, а не смещение

`SPEED_ZERO_MV = 150.0` работает как ворота: на пороге и ниже — штиль и ноль, выше —
откалиброванные милливольты уже и есть сигнал. **Вычитать его нельзя.** Вычитание (так код
делал до 2026-08-08) сдвигало всю шкалу вниз на целый пол: при 66.7 мВ на м/с это 2.2 м/с
ошибки в каждом отсчёте, настоящие 3 м/с превращались в 0.8. Симптом — станция выглядит
мёртвой, пока чашки не раскрутишь сильно.

Следствие, которое фиксом не лечится: скорости ниже ~2.3 м/с всё равно дают 0, и показание
прыгает с нуля сразу к ~2.3. Внизу нечего интерпретировать — прошивка может лишь перестать
портить остальную шкалу. Границу двигает только железо: `HAS_LEVEL_SHIFT 1` плюс резистор
47 кΩ с 3V3 на узел делителя. **Флаг включать только когда резистор впаян**, иначе показания
уедут вниз примерно на 6 м/с. Ноль после этого калибруется на месте через `/api/zero`.

- **координаты мачты** — полная точность это домашний адрес. В `secrets.h`

- **любые пароли** — только имя макроса из `secrets.h`, никогда значение. Пароли точки

- **IMEI / SN / ICCID модема, номер SIM** — при вставке AT-логов в `tasks/` заменять на

## Что чаще всего сбивает с толку

Полный разбор — в `FIRMWARE.md`, читать перед правкой `.ino`. Самое частое:

- Первые 30 секунд после старта батарея всегда читается как `absent` — `readBattery()`
  не вызывается в `setup()`. Нули в этот момент ничего не значат
- Питание по USB-разъёму ESP32 не доходит до TP4056, поэтому на столе плата честно рапортует
  `battery/absent` — это не баг
- В SSE-сокет писать только через `sseFlush()` (`lwip_send` + `MSG_DONTWAIT`). `sseClient.print()`
  при отстающем клиенте вешает `loop()` до 10 секунд, а вместе с ним и опрос датчика.
  `NetworkClient::setTimeout()` от этого не спасает, он вообще ни на что не влияет
- Детектор обрыва сигнала больше не ловит выдернутый провод: открытый вход читается тем же
  полом АЦП ~145 мВ, что и датчик на нуле. Видно только глухое замыкание на землю
- В строке Serial есть `loopMax` и `sseDrop` — по ним видно, тормозит ли `loop()` и не
  захлёбывается ли поток. `loopMax` больше нескольких мс = что-то блокирует

## Состояние проекта

Модуль на макетке, перфоплата и PCB отклонены осознанно. Раздел BOM в документе сборки —
источник истины по тому, что куплено, а что нет. Решения, уже отражённые в коде и документах:

- TP4056 + Schottky 1N5819 для разделения нагрузки (не YX-850)
- Делитель сигнала 10 кΩ снизу + 10 кΩ + 5 кΩ последовательно сверху (не 20 кΩ — старый
  номинал загонял АЦП в нелинейную зону)
- Мониторинг батареи на GPIO32 через делитель 100k/100k, тапится провод холдера
- Новый датчик 0–30 м/с без канала направления

## Соглашения при правке

- Три пласта движутся вместе. При смене пинов, API или математики — сразу править таблицу
  распиновки, BOM и диагностику в `wind-station-assembly.md` и поля дашборда, если изменилась
  форма API
- Документ сборки использует диаграммы Mermaid для потока питания и раскладки в корпусе —
  держать их согласованными с BOM
- Разделы про безопасность (обращение с батареей, проверка пресетов буста, предупреждения
  о полярности) несущие — не сокращать ради краткости
- Гайды по сборке генерируются из `images/bb_lib.py`, а не рисуются руками:
  `gen_*.py` → SVG, `build_*.py` → HTML. См. `images/BREADBOARD-STANDARD.md`
- `.ino` — комментарии и `Serial.print` по-английски, отступ 2 пробела, `#define` для пинов
  и флагов в SCREAMING_SNAKE, `const float` для калибровок, глобалы и функции camelCase,
  секции вида `// ===== PINS =====`. Плотность комментариев высокая: у каждой константы
  объяснение, какую физическую проблему она решает — держать этот уровень
- Python и вся документация — по-русски
- `wind-ui` — JSX, одинарные кавычки, без точек с запятой, отступ 2 пробела
