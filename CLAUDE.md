# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Тип проекта

DIY-железка, а не обычная кодовая база. Нет пакетного менеджера, нет тестов. Git с 2026-08-15,
ветка **`main`** (до 2026-08-16 называлась `master`). `origin` →
`git@github.com:temafey/ArduinoWindStation.git`, репозиторий **публичный** — что это значит
для содержимого, см. §Git. Взаимозависимые артефакты в плоском каталоге:

- `esp32_wind_station/esp32_wind_station.ino` — вся прошивка (~3800 строк, один файл; в `loop()` без RTOS, кроме клиента MQTT — тот крутится в своей задаче FreeRTOS, см. §Облачный канал)
- `esp32_wind_station/web_content.h` — **автогенерируемый**, руками не править
- `esp32_wind_station/gen_web_header.py` — генератор: `wind-ui/dist` → `web_content.h`
- `esp32_wind_station/secrets.h` — все пароли, **вне git**; шаблон `secrets.example.h`
  в git есть. Без `secrets.h` прошивка не собирается (см. §Секреты)
- `wind-dashboard.jsx` — главный файл дашборда (~3400 строк) **в корне репозитория**,
  уровнем выше `wind-ui/`. `wind-ui/src/App.jsx` — обёртка в пять строк, которая его
  импортирует. При переносе проекта одной папки `wind-ui` не хватит. С 2026-08-18 рядом
  с ним лежат ещё файлы, и это не дробление ради дробления — у каждого своя причина
  (список неполный, здесь только то, что чаще всего ищут):
  - `ui-kit.js` — палитра, шрифты, функции свечения и полярная геометрия. Вынесены, когда
    появился второй потребитель: две копии палитры расходятся всегда. Шрифты идут через
    CSS-переменные `--ui-sans`/`--ui-mono`, потому что гарнитура стала настройкой, а
    оформление здесь инлайновое — протаскивать её пропсами через полсотни компонентов было
    бы адом
  - `wind-map.jsx` — карта мира: своя проекция Меркатора, слои предупреждений NWS, донесений
    SPC, прогноза конвекции, отражаемости, суперклеточного экрана, городов и архива.
    Отражаемость — мировая тайловая мозаика RainViewer, а не растр NOAA на США: слой,
    который кончался на канадской границе, читался как поломка. Суперклеточный экран
    считается на месте из CAPE и векторного сдвига Open-Meteo по видимому куску карты
    (24 × 15 узлов — больше не влезает в строку адреса, сервер отвечает 414). Оба слоя
    по умолчанию пиксельные: клетка данных рисуется клеткой, а не сглаживается, — и оба
    переключаются тумблерами в «Основных» настройках (`pixelRadar`, `pixelCells`).
    Смерч рисуется воронкой с вихрем обломков, а направление — расширяющимся конусом
    неопределённости из сегмента TML, и только там, где служба сама указала движение.
    Колесо мыши слушается вручную через `addEventListener(..., { passive: false })`:
    React вешает `wheel` на корень пассивным, и с атрибутом `onWheel` карта
    приближалась вместе с уезжающей из-под курсора страницей
  - `wind-live.jsx` — «эфир»: живые снимки GOES-19/18 и радарная петля NWS. Кадры
    качаются через `fetch` с чтением потока, поэтому видно настоящий ход приёма в
    процентах и мегабайтах; где у хоста нет CORS, остаётся обычный `<img>` без полосы
  - `wind-tutor.jsx` — восьмибитный подсказчик и знак станции (киви в разрезе)
  - `wind-permissions.jsx` — панель разрешений браузера и объяснение, почему по HTTP их нет
  - `wind-themes.js` — темы оформления. Тема меняет не цвета, а материал панели, и делает
    это через переменные `--pnl-line` / `--pnl-bg` / `--pnl-shadow` / `--pnl-blur` /
    `--pnl-corner`. Иначе никак: оформление инлайновое, а инлайновый стиль сильнее любого
    правила — тема до панели просто не дотянулась бы. Каждая тема ещё выставляет
    «спутников» (материал подложки, скругление, свечение) через `apply(settings)`,
    но не затирает чужую картинку в сцене. Два места, где тема выходит за
    переменные: `glassRich()` решает, нужно ли вообще размытие под стеклом
    (под гладким градиентом размывать нечего — дашборд вешает класс `gl-deep`
    только когда под панелью картинка или зерно), а темы с полем `veil`
    получают плёнку в три слоя поверх всего экрана
  - `wind-switch.jsx` — тумблер для настроек с двумя значениями плюс `SwitchGlyph` —
    его вид без обработчиков, для случаев, когда переключателем работает вся кнопка
    целиком (слой карты, режим светодиодов): вложенная кнопка была бы недопустимой
    разметкой. Стили отдаются строкой `SWITCH_CSS` и вклеиваются в общий `<style>`
  - `storm-archive.js` — справочный архив смерчей с рейтингами EF по обследованиям NWS/NCEI
  - `world-rings.js` — **автогенерированные** контуры суши (Natural Earth 110m, 84 кольца,
    8.8 КБ gzip). Руками не править
  - `world-cities.js` — короткий список городов для подписей на карте
- `wind_display/` — **отдельная плата-дисплей** в корпусе: ESP32-2432S028 («Cheap Yellow
  Display», CYD 2USB, ST7789 + тач XPT2046, мост CH340C). Свой скетч `wind_display.ino`
  (LovyanGFX + ArduinoJson), шрифты с кириллицей `display_fonts.h` — **автогенерируемый**
  из DejaVu Sans генератором `gen_display_fonts.py`; стеклянные фоны (Tinted, iOS 26/27)
  `glass_bg.h` — тоже **автогенерируемый**, генератор `gen_glass.py`, раскладка скетча
  обязана совпадать с его `PANELS_*`. Данные получает **по одному проводу**
  от станции (GPIO23 → CN1 IO27, UART 115200, JSON-кадр `/api/data` 5 раз в секунду),
  не по WiFi — клиент на точке навсегда заглушил бы поиск домашней сети. Разбор,
  разводка и заливка — `DISPLAY.md`. «TPM408-2.8» — маркировка стекла, а не платы
- `wind-ui/` — Vite-обвязка дашборда (React 19 + Vite 8, чистый JS, без TypeScript)
- `wind-station-assembly.md` — руководство по сборке (BOM, разводка, распиновка, диагностика)
- `FIRMWARE.md` — разбор прошивки: архитектура, тайминги, калибровки, ловушки отладки
- `FLASHING.md` — заливка, вход в download mode, разбор ошибок
- `PUBLISHING.md` — публичная копия дашборда на статическом хостинге
- `A7670E-DRIVERS.md` — драйверы и первый запуск платы 4G/GPS на Windows; рядом
  `drivers/` (вендорский архив, `install-drivers.ps1`, `at.ps1` для AT-сеансов).
  Модуля в станции пока нет, это задача `tasks/10-a7670e-4g-gps.md`

Документация, строки UI, Serial-логи — по-русски. Комментарии в `.ino` — по-английски.
Имя папки скетча обязано совпадать с именем `.ino`, иначе arduino-cli скажет
«в скетче отсутствует основной файл».

## История версий

Версия от 2026-08-13 (форк `WindCatcher`, собран на другой машине) перенесена сюда 2026-08-15
и стала основной. Предыдущая версия — клиент домашней WiFi-сети с пулом сетей в NVS — лежит
целиком в `archive/firmware-v2-multiwifi-2026-08-02/`. Каталог остаётся на месте: он старше
первого коммита (2026-08-15), поэтому история git до него не достаёт и откат этих версий —
по-прежнему только копированием файлов из `archive/`.

**Что залито на плату сейчас.** С 2026-08-18 на чипе актуальная сборка из этого дерева:
AP+STA, AT-консоль модема, `/api/site`, защита эндпоинтов записи и текущий дашборд.
Признак в Serial — строка телеметрии с `mV`/`zero`/`loopMax` и сообщения `Uplink … joined`.
Проверять, что именно на плате, надёжнее всего по `/api/wifi`: наличие `uplinkSsid`
означает сборку не старее 08-15, а `/api/site` — не старее 08-18.

## Архитектура — как части связаны

Правка любого из трёх пластов (прошивка / дашборд / документ сборки) без правки остальных
ломает систему. **Редактировать как набор, а не по отдельности.**

### Сеть: точка доступа всегда, домашняя сеть — вдобавок

Точка доступа безусловна: поднимается на старте, и **ни одна строка прошивки её не гасит**.
Это главный урок старого станционного режима — плата держала пул сетей в NVS, на старте
входила в сильнейшую, и `softAPdisconnect()` убивал AP через ~15 с после включения; станция
пропадала с телефона. Тот режим не вернулся и не вернётся.

С 2026-08-15 добавлен **AP+STA** (`WIFI_AP_STA`): плата одновременно раздаёт свою сеть и
входит в домашнюю. Разница со старым режимом принципиальная — подключение к сети делается
**в дополнение** к точке доступа, а не вместо неё, и провал подключения не стоит ничего,
кроме самого аплинка. Настраиваемая часть не вернулась: пул сетей в NVS,
`/api/wifi?add|del|connect`, перескан раз в 30 с и трёхминутный фолбэк-AP по-прежнему мертвы,
а аплинк — константа в `.ino`, а не форма на странице.

- SSID `WindStation`, **WPA2, пароль — `SECRET_AP_PASSWORD` в `secrets.h`** (ESP32 требует
  8..63 символа; короче — `softAP()` молча поднимет открытую сеть), не более 4 клиентов
- **Режим шифрования задан явно** — `WIFI_AUTH_WPA2_PSK` + `WIFI_CIPHER_TYPE_CCMP`
  аргументами `softAP()`, а не умолчанием ядра (2026-08-23). До этого вызов кончался
  на `apMaxClients`, и режимом было то, что в ядре текущего дня лежит в
  `WIFI_AP_DEFAULT_AUTH_MODE`. Сохранённый профиль этой сети на ноутбуке —
  `WPA3SAE`, то есть когда-то точка выходила в эфир вовсе не как WPA2. А точка
  WPA3-SAE по стандарту обязана иметь защиту управляющих кадров — здесь же
  `pmf_cfg` был весь в нулях (`APClass::create()` делает `memset` всей
  `wifi_config_t` и `pmf_cfg` не восстанавливает, ровно та же история, что с
  `dtim_period`). Supplicant Android такую точку проверяет и уходит: «Connecting…»,
  тишина, сеть остаётся в списке. Windows — пожимает плечами и подключается.
  **Это и есть вся история «ноутбук заходит, телефон никогда».** Расстояние,
  мощность и поиск домашних сетей тут ни при чём
- `pmf_cfg` возвращён на документированное умолчание IDF: `capable = true`,
  `required = false`. Не выше: `required` отрезал бы клиентов, которые PMF не умеют
- Режим точки печатается в Serial при старте (`AP security: …`). Раньше его нельзя
  было узнать иначе как открыв сохранённый профиль на уже подключившейся машине —
  плохой способ выяснить, что половина устройств в доме зайти не может
- **После смены режима старые профили надо забыть.** Ноутбук, у которого сохранён
  `WPA3SAE`, к WPA2-точке может не подключиться, пока сеть не «забыта» и пароль
  не введён заново. Это разовое действие на каждом устройстве, которое подключалось
  до 2026-08-23
- Адрес `http://MyWindProbeBETA.org` — резолвится собственным DNS-сервером платы (catch-all
  на этот адрес), поэтому работает и на Android, где `.local` ненадёжен. `192.168.4.1` работает
  всегда. Captive-portal анонсируется через DHCP option 114
- mDNS-метка `mywindprobebeta` → `mywindprobebeta.local`, под этим же именем плата видна
  в списке сетевых портов Arduino IDE. Пароль OTA — `SECRET_OTA_PASSWORD` в `secrets.h`
- Домен на нас не зарегистрирован. Пока устройство подключено к станции, настоящий сайт на
  этом домене для него будет затенён — но у AP всё равно нет аплинка

**Аплинк** — `SECRET_HAS_HOME_NETWORK` и `SECRET_HOME_NETWORKS` в `esp32_wind_station/secrets.h`
(**файл вне git**, см. раздел «Секреты» ниже). Флаг `0` = чистая точка доступа, и тогда кода
ретраев не существует вовсе (мачта, дача, поле).

- **Список, а не одна сеть.** `SECRET_HOME_NETWORKS` — пары `{ssid, password}`,
  порядок = приоритет. Добавить сеть = дописать строку в `secrets.h` и перезалить;
  форм и NVS для этого нет и не будет. Это один макрос на несколько строк: каждая строка,
  кроме последней, кончается `\`, а комментарии внутри — **только `/* */`**, потому что `//`
  съел бы остаток склеенной строки вместе со следующими сетями
- **Только 2.4 ГГц.** У ESP32 нет радио на 5 ГГц, поэтому половина `-5G` двухдиапазонного
  роутера для него невидима — сколько её ни вписывай
- Радио одно, канал общий: AP стартует на канале 1, а когда аплинк входит в роутер на другом
  канале, **точка уезжает следом**. Клиенты AP при этом один раз отваливаются и
  переподключаются. На однорадийном чипе это неизбежно — потому поиск аплинка и запускается
  последним делом в `setup()`. Вдали от дома ассоциации не происходит вообще, и канал 1
  остаётся неподвижным
- **Сначала скан, потом ассоциация** (с 2026-08-23). До этого список обходился вслепую:
  `WiFi.begin()` на каждое имя по очереди, каждому `STA_ASSOC_MS` = 12 с на молчание.
  Шесть сетей = **72 с метаний по каналам после каждого включения** — и ровно в это окно
  человек в поле пытается подключить телефон. Ассоциация телефона такого не переживает,
  ноутбук ретраит дольше и просачивается: отсюда симптом «ноутбук подключается, телефон
  нет». Теперь один асинхронный скан (`STA_SCAN_MS_PER_CHAN` = 120 мс × 13 каналов ≈ 1.6 с)
  отвечает сразу за весь список, и если ни одной знакомой сети в эфире нет — ни одного
  `WiFi.begin()` не делается. Из найденных берётся **самая ранняя в списке**, не самая
  громкая: порядок в `SECRET_HOME_NETWORKS` — это приоритет. Канал и BSSID передаются
  в `begin()`, чтобы ассоциация шла на одном канале, а не искала имя по всем
- **Провалившийся кандидат вычёркивается до конца прохода** (`staFailedMask`, бит на сеть).
  Без этого приоритет становился тупиком: `best` считается заново на каждом скане, поэтому
  первая по списку сеть, которая **в эфире, но не пускает** (сменили пароль, сосед с тем же
  именем, роутер отказывает), выбиралась бы снова и снова, а всё, что ниже неё в списке,
  было бы недостижимо — хотя слепой обход до этих сетей доходил. Маска очищается при
  успешном подключении и когда проход перебрал всё, что видел. Отсюда же и место паузы:
  между кандидатами одного прохода её нет, удвоение случается **только** когда проход
  кончился впустую — иначе вторая сеть уезжала бы на полчаса из-за того, что сломана первая
- **Молчание, пока кто-то на точке.** Если прошлый скан не нашёл ничего своего
  (`staNoneInRange`) и на AP есть клиент — плата не сканирует вовсе. Дешёвый скан всё равно
  оставляет 1.6 с дыру посреди чужого сеанса, а в поле искать нечего. Проверит снова,
  когда клиент уйдёт
- Попытка бросается сразу по `WL_NO_SSID_AVAIL`/`WL_CONNECT_FAILED`, не досиживая 12 с,
  и завершается `WiFi.disconnect(false, false)` — иначе драйвер продолжает ретраить сам,
  уводя радио с канала AP. Это единственный `disconnect()` вне `setup()`, и точки он
  не касается
- Пауза с удвоением 30 с → 10 мин (`STA_RETRY_MIN_MS`/`STA_RETRY_MAX_MS`) — между поисками.
  `WiFi.setAutoReconnect(false)`, чтобы ретраями рулило одно место
- `serviceUplink()` вызывается из `loop()` каждый проход и **никогда не блокирует** —
  `WiFi.begin()` только запускает ассоциацию, результат читается на следующих проходах.
  Блокирующий `wifiMulti.run()` на 30 с из старого режима — ровно то, чего здесь нет
- На старте прошивка стирает креды STA из NVS (`WiFi.disconnect(true, true)` до
  `persistent(false)`): аплинком должно быть то, что написано в исходнике, а не остатки
  от какой-то прошлой сборки — раздел `nvs` не переписывается при OTA и живёт вечно
- IP в домашней сети виден в Serial при подключении, в `/api/data` (`staIp`) и в `/api/wifi`
  (`uplinkIp`). Какая именно сеть из списка отозвалась — `staSsid`/`uplinkSsid` (берётся
  из драйвера, не из констант), весь список имён — `uplinkKnown` в `/api/wifi`
- Пароли аплинка — в `secrets.h`, не в `.ino` и не в git (было наоборот до 2026-08-16,
  историю почистили). В скомпилированный `.bin` они всё равно попадают открытым текстом:
  прошивка не пишет NVS, деть их некуда — но это уже вопрос к тому, кому отдаётся бинарник

### Секреты: `esp32_wind_station/secrets.h`

Единственное место, где лежат пароли. **Файл в `.gitignore`**, в git — только шаблон
`secrets.example.h`. На свежем клоне: `copy secrets.example.h secrets.h` и вписать сети.

- Без `secrets.h` скетч **не собирается** — в `.ino` стоит `#error` под `__has_include`.
  Это намеренно: молчаливый фолбэк дал бы плату, поднявшую **открытую** сеть, а такую
  ошибку замечают только когда на ней уже кто-то сидит
- Макросы: `SECRET_AP_PASSWORD` (WPA2 точки, 8..63 символа — короче, и `softAP()`
  молча откроет сеть), `SECRET_OTA_PASSWORD`, `SECRET_HAS_HOME_NETWORK` +
  `SECRET_HOME_NETWORKS`, `SECRET_STATION_LAT`/`LON`/`ALT_M` (координаты мачты — полная
  точность это домашний адрес, потому они тоже здесь, а не в скетче)
- Облачный канал (**с 2026-09-12 читаются прошивкой и работают**): `SECRET_HAS_CLOUD`
  (`0` = весь MQTT-клиент выключен из сборки, `1` = включён), `SECRET_MQTT_HOST`/`PORT`/

### Контракт HTTP API (прошивка ↔ дашборд)

Порт 80, у всех ответов `Access-Control-Allow-Origin: *`. Основной канал данных — SSE
(`/api/stream`, 20 Гц); дашборд дополнительно опрашивает `/api/data` как heartbeat и фолбэк —
раз в 5 с пока поток жив, раз в 1 с иначе. **Не чаще 1 Гц**: WebServer всегда закрывает
соединение, а lwIP держит 16 TCP PCB по 60 с в TIME_WAIT каждый.

- `GET /api/data` — JSON: `speed`, `direction`, `dirPresent`, `gust`, `speedMv`, `speedZeroMv`,
  `speedSpreadMv`, `speedMax`, `ledGreen`, `ledYellow`, `ledRed`, `ledWifi`, `ledAuto`,
  `battery`, `batteryPercent`, `batteryPresent`, `chargeState`, `powerSource`, `wifiRssi`,
  `adcError`, `staSsid`, `staConnected`, `staIp`, `hostname`, `uptime`, `resetReason`,
  `timeValid`, `epoch`, `loopMax`, `logMs`, `sseDrop`, `siteLat`, `siteLon`, `siteAltM`
  и — условно, только когда есть что сказать — `pppState`, `pppIp`, `netOperator`,
  `netRssi`, `netMode`, `netAttached`, `cloudConnected`, `cloudError`.
  Дашборд кладёт сырой ответ прямо в состояние `data` — переименования и смена типов
  только синхронно с ним.
  - **Условные поля именно условны: нет данных — нет ключа**, а не `0`, `""` или `null`.
    Дашборд различает «ключа нет» (строку не рисовать вовсе) и «ключ есть, значение
    пустое» (написать «нет данных»), и умолчание стёрло бы это различие. Ноль вместо
    отсутствующего показания — худшее, что может сделать метеостанция: `0 дБм` это
    уровень сигнала, а не «модема нет». Правило то же, что у `dirPresent`/`batteryPresent`,
    только выраженное отсутствием ключа, а не отдельным флагом
  - ⛔ **`siteLat` / `siteLon` — ТРИ знака после запятой, и это граница безопасности,
    а не формат вывода.** Ровно этот же JSON уходит в retained-топик `state`, который
    читает учётка зрителя из публичного бандла — то есть всё, что попало в кадр, публично.
    Три знака это ~100 м: хватит навести карту, мало чтобы получился адрес. Полная
    точность живёт в `/api/site`, который отвечает только в своей сети. И ошибка здесь
    необратима в одну сторону: retained-сообщение с пятью знаками пролежит на брокере
    до перезаписи, отозвать его нечем. `siteAltM` — один знак, высота адресом не является
  - `pppState` / `pppIp` — состояние 4G-аплинка (`stopped` / `attaching` / `dialing` / `online` / `failed`).
    Появляются только при `HAS_MODEM 1 && MODEM_USE_PPP 1`, `pppIp` — только когда адрес
    действительно есть
  - `netOperator` / `netRssi` / `netMode` / `netAttached` — **из кэша, который обновляется
    раз в 60 с**, а не из кадра. Под ними четыре AT-раунда через CMUX, и делать их на 20 Гц
    значило бы остановить сэмплер. Цена учтена в `busyMaxMs` (`/api/modem`), а не в
    `loopMax`: иначе раз в минуту метрика «что-то голодает опрос датчика» показывала бы
    собственную диагностику — ровно та история, из-за которой пришлось выделить `logMs`.
    Имя оператора приходит из сети свободным текстом и наружу идёт только через фильтр:
    одна кавычка в alpha-tag ломает не поле, а весь объект, у каждого зрителя retained-топика
  - `cloudConnected` / `cloudError` — только при `SECRET_HAS_CLOUD 1`; `cloudError`
    появляется, лишь когда ошибка есть
  - `resetReason` — почему чип стартовал в прошлый раз: `poweron` / `brownout` / `panic` /
    `watchdog` / `software` / `external` / `deepsleep` / `unknown`. Плитка «Аптайм» дописывает
    причину к заголовку и красит значение оранжевым при `brownout`; обычное включение
    не дописывает ничего. Смысл узкий и вполне конкретный: станция в поле работает от
    батареи, а батарея, проседающая на передаче, роняет плату в ресет — снаружи это
    выглядит как «не пускает телефон», и один аптайм такое от свежего включения
    не отличает
  - `loopMax` / `logMs` / `sseDrop` — те же числа, что в строке телеметрии Serial, и с тем же
    моментом обнуления: «с прошлой строки телеметрии», а не «с включения». Раньше они
    жили только в Serial; вынесены в API потому, что кабель перестал быть бесплатным —
    открытие USB-порта на этой плате дёргает DTR и перезагружает чип, а перезагрузка
    мимо `ArduinoOTA.onStart()` оставляет модем в CMUX, то есть посмотреть `loopMax`
    кабелем теперь стоит 4G-аплинка до снятия питания с модуля.
    **`logMs` (добавлено 2026-09-12) — сколько заняла сама строка телеметрии**, и оно
    из `loopMax` **вычтено**. Разделить пришлось потому, что число врало на себя же:
    `Serial.printf` выполняется, потом `loopMaxMs` обнуляется, и первым, что попадает
    в свежий счётчик, оказывается стоимость этой же диагностической строки. На 115200
    длинная строка — это 12–13 мс блокировки, и `loopMax` показывал ровно их, то есть
    отвечал на вопрос, которого никто не задавал. Теперь `loopMax` значит «что-то
    голодает опрос датчика», а `logMs` — «консоль медленная»: две разные беды, у
    которых было одно число
  - `timeValid` / `epoch` — есть ли у станции настоящая дата и какая (UTC, секунды
    эпохи; `0` = не синхронизировано). Это не украшение, а **ворота перед первым TLS**:
    сертификат проверяется по часам, и плата, стартовавшая в 1970 году, отвергнет любой
    действующий сертификат. Время берётся SNTP по маршруту по умолчанию (дома WiFi,
    на мачте PPP) и **намеренно не из часов модема**: при выставленном `AT+CTZU=1`
    сеть время отдаёт, но `AT+CCLK?` вернул `26/09/11,16:57:42+00` при настоящем UTC
    `08:57:42` — дата верна, ход верен, время суток ровно на 8 часов вперёд при
    заявленном нулевом смещении. Восемь часов — это Пекин; для срока сертификата такая
    ошибка безобидна, для метки времени отсчёта — нет. `0` читать как «не знаю», а не
    как 1970 год
  - `speed` и `gust` — **два знака после запятой**: при одном квантование в 0.1 м/с было
    грубее собственного шума датчика после усреднения по 32 отсчётам
  - `speedMv` / `speedZeroMv` / `speedSpreadMv` — диагностика, дашборд их игнорирует: сырые
    усреднённые мВ на пине скорости, действующая точка нуля и разброс одной пачки отсчётов
    (по нему видно наводку). Позволяет проверить пол АЦП без USB-кабеля
  - `hostname` теперь отдаёт `MyWindProbeBETA.org` — адрес для человека, а не mDNS-метку
  - четыре поля `led*` — строки режима `off` / `on` / `blink` (дашборд ещё нормализует
    булевы из прошивок до появления blink); `ledAuto` остаётся булевым
  - `chargeState` — `absent` / `charging` / `full` / `discharging`, `powerSource` —
    `external` / `battery`. Оба берутся со статусных линий TP4056 на GPIO13/19, а не
    угадываются по напряжению — см. раздел CHRG/STDBY в документе сборки
  - `staSsid` / `staConnected` / `staIp` — аплинк (добавлены 2026-08-15, дашборд их пока
    игнорирует). `staIp` — единственный способ узнать адрес платы в домашней сети,
    не открывая роутер или Serial. `staSsid` — какая сеть из списка отозвалась (`null`,
    пока связи нет). При `HAS_HOME_NETWORK 0` — `null` / `false` / `null`
  - `wifiRssi` — сигнал того канала, через который скорее всего смотрят: если к AP кто-то
    подключён, это лучший из клиентов; если AP пуста, а аплинк есть — `WiFi.RSSI()` домашней
    сети. `0`, когда нет ни того ни другого
  - **опциональные датчики** (контракт согласован 2026-08-18, в прошивке их пока нет):
    `tempC`/`tempPresent`, `humidity`/`humidityPresent`, `pressureHpa`/`pressurePresent`,
    `rainMm`/`rainPresent`, `lux`/`luxPresent`, `uvIndex`/`uvPresent`. Дашборд уже умеет
    их показывать и рисует карточку **только** при истинном флаге присутствия — по тому
    же правилу, что направление и батарея. Флаг обязателен: ноль вместо отсутствующего
    датчика это худшее, что может сделать метеостанция, потому что 0 °C — это мороз,
    а не «термометра нет». Значения всегда в СИ, пересчёт делает дашборд. Точка росы
    (формула Магнуса) и «ощущается как» (формула NWS, только в холод при ощутимом ветре)
    считаются на клиенте и датчиками не являются — при выходе за область определения
    их просто нет
- `GET /api/stream` — Server-Sent Events, тот же JSON кадрами `data: {...}\n\n` каждые 50 мс.
  Подписчик один: новое подключение вытесняет предыдущее. Работает потому, что сокет
  `NetworkClient` у WebServer — `shared_ptr`, и прошивка держит копию после конца запроса
- `GET /api/led?auto=true|false` и `?green=…&yellow=…&red=…&wifi=…` со значениями
  `off` / `on` / `blink` (старые `true`/`false` ещё разбираются); действует только при `auto=false`
- `GET /api/gust` — сбросить пиковый порыв
- `GET /api/zero` — калибровка нуля на месте, с неподвижными чашками: без аргументов показывает
  действующее значение и текущий отсчёт, `?set=` принимает текущий (⚠️ **со знаком равенства**:
  голый `?set` WebServer выбрасывает, см. `/api/modem`), `?set=374.0` — явный,
  `?reset=1` возвращает к константе (голый `?reset` тоже выбрасывается — см. ниже). **Только в RAM**: прошивка никогда не пишет NVS, поэтому
  ответ отдаёт готовую строку константы для вставки в исходник
- `GET /api/wifi` — только чтение: `{mode:"ap", apOnly:true, current, ip, clients, host,
  uplinkSsid, uplinkConnected, uplinkIp, uplinkRssi, uplinkKnown, max:0, nets:[]}`.
  `uplinkKnown` — имена всех сетей из `homeNetworks[]` (пароли не отдаются никогда, ни здесь,
  ни где-либо ещё): по нему видно, что эта сборка вообще будет пробовать. Настраивать по-прежнему
  нечего, но эндпоинт оставлен — встроенный дашборд его опрашивает. **`apOnly` остаётся
  `true` и при живом аплинке**: дашборд читает этот флаг как «настроек сети нет», что правда,
  а `false` заставил бы старый вшитый UI показать редактор поверх удалённых эндпоинтов
- `GET /api/site` — где стоит станция: `{lat, lon, altM, host}` из `SECRET_STATION_*`
  в `secrets.h`. Появился 2026-08-18 и закрывает конкретную дыру: на копии, отданной
  платой по обычному HTTP, браузер **отказывается** сообщать место смотрящего
  (геолокация только для защищённого контекста), поэтому место самой станции —
  единственная реальная точка, на которую карте можно опереться. Полная точность
  здесь намеренна: это своё устройство в своей сети, а правило округления до трёх
  знаков — про то, что уходит в git и в документацию, а не про то, что плата говорит
  своему же дашборду. `0/0` означает «не настроено», и дашборд читает это именно так,
  а не как точку в Гвинейском заливе
- **Защита эндпоинтов записи.** `/api/led`, `/api/gust`, `/api/zero` и `/api/at` начинаются
  с `crossSiteWrite()`. Угроза не в соседе по локальной сети, а в **любой странице,
  уже открытой в том же браузере**: API принимает обычные GET-ы, поэтому произвольный
  сайт может отправить запрос на `192.168.4.1/api/led`, и браузер его отправит.
  Wildcard `Access-Control-Allow-Origin` прячет от чужого скрипта только **ответ** —
  запрос всё равно доходит и срабатывает, а через `/api/at` он мог бы отправить SMS.
  Собственный GET дашборда заголовка `Origin` не несёт вовсе, поэтому «Origin есть
  и он не наш» — это ровно межсайтовый случай и ничего больше; такой запрос получает
  403. `localhost` в белом списке намеренно: это `npm run dev`, нацеленный на живую
  плату. Работает только вместе с `server.collectHeaders({"Origin"})` — WebServer
  хранит лишь те заголовки, о которых его попросили, и без этого вызова guard молча
  пропускает всё
- **Заголовки безопасности** на встроенных страницах (`sendPageSecurity()`):
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` и CSP.
  Секретным контекстом это страницу **не делает** — это умеет только настоящий TLS,
  а сертификат доверенного центра на приватный IP не выдаст никто; но это та часть,
  которая бесплатна. `Permissions-Policy` явно **разрешает** геолокацию своему
  происхождению, чтобы единственным препятствием остался сам браузер. В CSP
  `img-src`/`connect-src` пускают `https:` целиком: карта мира тянет предупреждения
  с `api.weather.gov` и растры с NOAA, а эти хосты не наши, чтобы их прибивать.
  `'unsafe-inline'` для стилей — потому что весь дашборд свёрстан инлайн-стилями.
  В `img-src` обязателен **`blob:`**: «Эфир» качает кадр GOES через `fetch` (ради полосы
  приёма) и отдаёт собранный `Blob` в `<img>`, а выбор фона так же меряет фотографию перед
  сжатием. `'self'` блобы не покрывает, и без них обе функции ломаются **только на плате** —
  в `npm run dev` и на публичной копии заголовка нет. Причём молча: у фона CSP роняет
  `img.onerror`, и код объявляет нормальный снимок «не картинкой»
- `GET`/`POST` `/api/at` — AT-консоль модема A7670E, только при `HAS_MODEM 1`. Появилась
  потому, что модуль сидит на макетке наклейкой вниз и его micro-USB недоступен. Ответ —
  `text/plain`: эхо команды, сырые байты модема, трейлер `-- rx=… total=… waited=…мс`.
  `?cmd=AT%2BCSQ` — из браузера (**`+` обязан быть `%2B`**, WebServer декодирует `+` как
  пробел); `POST` с `Content-Type: text/plain` и командой в теле — из терминала без
  экранирования (с дефолтным для curl form-типом `+` снова станет пробелом); без
  аргументов — забрать URC и поток NMEA. `&wait=N` (0…3000, по умолчанию 500) — ожидание
  ответа, **оно блокирует `loop()`** и видно в `loopMax`; выход досрочный по финальному
  коду. Долгие команды — с `wait=0`, ответ следующим запросом. `total` — счётчик всех
  принятых байтов: ноль при живом эхе означает провода или скорость, а не прошивку.
  `&pins=RX,TX` (только 25/26/27) и `&baud=N` переоткрывают UART2 **на лету, без
  перезаливки** — какой из двух проводов сел на какой пин, иначе стоит USB-сессии
  с кнопками. Только в RAM, как `/api/zero`: рабочее сочетание переносить в константы.
  **Единственный эндпоинт без `Access-Control-Allow-Origin`** — здесь команда может
  отправить SMS, и чужая вкладка не должна суметь прочитать IMEI/ICCID.
  С 2026-09-11 у него **два канала**: пока PPP не поднят — сырой `Serial2`, как раньше;
  когда поднят — те же запросы идут через `PPP.cmd()` по AT-каналу CMUX, и консоль
  работает **одновременно с трафиком**. В трейлере видно, какой канал отвечал
  (`via=CMUX state=online`). `&pins=`/`&baud=` при поднятом PPP молча игнорируются:
  `Serial2` закрыт, и второй UART на те же ноги — это драка за пины
- `GET /api/modem` — 4G-аплинк, тоже только при `HAS_MODEM 1` и `MODEM_USE_PPP 1`.
  Без аргументов — дёшево, только факты уровня netif (`state`, `ip`, `gw`, `dns0/1`,
  `routePrio`, `isDefault`, `tries`, `busyMaxMs`, `lastError`), ни одного слова модему.
  `?radio=1` добавляет RSSI, оператора и режим сети — четыре AT-раунда, потому и
  по запросу. `?probe=1` открывает TCP на `8.8.8.8:53` **с сокета, привязанного к
  PPP-адресу** — это и есть проверка «у станции есть интернет через модем», и привязка
  обязательна: дома WiFi-аплинк имеет приоритет маршрута 100 против 20 у PPP, и обычный
  сокет ушёл бы через него, отрапортовав успех за чужой интерфейс. `?ntp=1` тем же
  приёмом спрашивает дату у NTP по UDP — «узнает ли мачта, какое сегодня число, через
  4G», то есть предусловие TLS; дома синхронные часы на этот вопрос не отвечают, потому
  что SNTP уходит через WiFi. Сервер задан **числом** (`216.239.35.0`), чтобы проверка
  не зависела от резолвера. `?dns=NAME` резолвит имя вручную с того же привязанного
  сокета, спрашивая тот резолвер, который был пришпилен интерфейсу — **значение аргумента
  и есть имя** (`?dns=1` берёт имя по умолчанию). Проверить пин иначе нельзя: таблица
  резолверов в lwIP глобальная, и `dnsIP()` читает из неё домашний роутер. `?off=1`
  отдаёт UART
  обратно консоли и прекращает ретраи, `?on=1` включает и пробует немедленно. Защищён
  `crossSiteWrite()` и **тоже без CORS** — `?off=1` роняет аплинк.
  ⚠️ **`=1` обязательно.** `WebServer::_parseArguments()` **выбрасывает** аргумент без
  `=` (`log_e("arg missing value")`), поэтому голый `?probe` до `hasArg()` не доходит
  вовсе и эндпоинт отвечает так, будто ничего не спрашивали. Молча. Из этого же следует,
  что **документированный ниже `/api/zero?set` без значения не работает** — рабочая
  форма `?set=` или `?set=374.0`
- `GET /api/cloud` — облачный канал, только при `SECRET_HAS_CLOUD 1` (иначе эндпоинта
  нет вовсе — 404 это и есть ответ «в этой сборке облака нет»). Без аргументов — JSON
  состояния: `enabled`, `started`, `connected`, `host`, `port`, `user`, `stationId`,
  `sessionId`, `clockValid`, `hmacKey`, `connects`, `errors`, `pubLive`, `pubDrop`,
  `cmdOk`, `cmdBad`, `cmdLastId`, `aggTotal`, `aggPending`, `heapFree`, `heapMin`,
  `via`, `boundIf`, `otaLast`, `lastError`. Пароль и HMAC-ключ **не отдаются никогда**, ни здесь,
  ни где-либо ещё; `hmacKey` — только булево «ключ разобран и пригоден».
  `sessionId` отдаётся намеренно: без него оператор не сможет подписать команду
  (см. §Облачный канал). Аргументы:
  - `?off=1` / `?on=1` — выключить и включить канал. Только в RAM, как `/api/zero`:
    после перезагрузки снова включён
  - `?via=ppp` / `?via=auto` — **пришпилить сокет MQTT к модему** или вернуть выбор
    таблице маршрутов. Под капотом `SO_BINDTODEVICE` через `esp_mqtt_client_config_t
    .network.if_name`; интерфейс выбирается один раз при инициализации, поэтому смена
    рвёт и пересоздаёт клиента. Сессионный нонс при этом **не переиздаётся** — он
    принадлежит загрузке, а не сокету, и команды, подписанные минуту назад, переживают
    смену. `boundIf` показывает, что реально пришпилено (`pp4` = PPP, пусто = маршрут
    по умолчанию). Нужно ровно дома: у WiFi приоритет маршрута 100 против 20 у PPP,
    и без привязки проверка «работает ли TLS по 4G» молча уходила бы через роутер.
    На мачте PPP — единственный маршрут, и аргумент там не нужен
  `otaLast` — чем кончилась последняя попытка pull-OTA (пусто = её не было с прошлой
  загрузки). Живёт здесь, а не в `/api/data`, намеренно: кадр данных уходит в публичный
  retained-топик `state`, а строка вида «`sha256 mismatch, 1548064 B discarded`» —
  диагностика для своей сети, не сводка для интернета. Тот же случай, что `/api/site`.
  Защищён `crossSiteWrite()` и **без CORS**, по той же причине, что `/api/modem`:
  `?off=1` роняет канал, а чужой вкладке незачем читать, куда станция отчитывается
- `GET /` и хешированные `/assets/*` — встроенный дашборд (gzip из PROGMEM,
  `Content-Encoding: gzip`), маршруты регистрируются из `web_content.h`. Только GET, на HEAD 404

Дашборд, отданный самой платой (порт 80, не localhost), использует `window.location.host`
и игнорирует localStorage. Константа `PUBLIC_COPY` в `wind-dashboard.jsx` отличает копию на
хостинге (HTTPS) от копии на плате (HTTP). **Один бандл на оба места остаётся принципом**,
и отдельной сборки для публикации нет — но с 2026-09-12 у него есть **одно намеренное
исключение, и его надо знать**: облачный транспорт (`wind-cloud*`) собирается в отдельный
чанк, который в `web_content.h` не попадает. Причина не в размере, а в том, что в этом чанке
лежит учётка зрителя, а `web_content.h` коммитится в публичный репозиторий и зашивается
во флеш. Разбор трёх слоёв изоляции — в §Облачный канал.

С этого же момента `PUBLIC_COPY` перестала означать «живых данных здесь быть не может»:
для станции с `cloudId` публичная копия показывает настоящий ветер через брокер. Различать
надо три разных признака, которые до облака выглядели одним: `PUBLIC_COPY` — «прямого HTTP
к плате нет» (**лечится облаком**), `!GEO_AVAILABLE` — «браузер не отдаёт координаты
смотрящего» (не лечится ничем, кроме HTTPS), `st.cloudId` — «у ЭТОЙ станции канал есть».

### Облачный канал: MQTT через брокер (прошивка ↔ брокер ↔ публичный дашборд)

Работает с 2026-09-12, проверено на железе и по WiFi, и по 4G. Включается
`SECRET_HAS_CLOUD 1`, и обходится в ~125 КБ флеша (esp-mqtt, TLS, корневые
сертификаты); при `0` этого кода в сборке нет вовсе.

**Почему брокер, а не сервер на станции.** Оператор даёт CGNAT-адрес — входящее соединение
до станции невозможно в принципе, и никакой проброс портов этого не чинит. Поэтому обе
стороны ходят наружу, а встречаются на брокере (кластер HiveMQ, TLS 8883). Из этого же
следует, что **OTA по 4G — pull-only**: `espota` требует входящего соединения, значит
обновление это ссылка, по которой станция идёт сама. Сделано и проверено на железе
2026-09-12; инструкция — раздел 2a в `FLASHING.md`. Три вещи, которые надо знать, прежде
чем этим пользоваться:

- **доверие даёт подпись команды, а не TLS.** `url` и `sha256` едут внутри подписанной
  команды, хеш сверяется **до** того, как раздел объявляется загрузочным. Подменённый
  файл не сойдётся с хешем, подменённый хеш — с подписью, а провалившееся обновление
  не трогает работающую прошивку (проверено: аптайм не сбрасывается). Поэтому `http://`
  разрешён и должен остаться: `CLOUD_ROOT_CA` — это Let's Encrypt, и https-only
  обновление добавило бы станции второй срок годности;
- ⛔ **но `.bin` несёт все пароли станции открытым текстом** — ключи домашних сетей,
  пароли точки и OTA, учётку брокера, HMAC-ключ команд. Значит `https://` предпочтительнее
  везде, где корень хоста есть в прошивке, а сам файл не должен лежать на публичном
  хостинге и должен удаляться сразу после заливки. Полежал открыто — пароли считать
  сгоревшими и менять, ровно как с секретом в публичном коммите;
- ⚠️ **редирект со сменой схемы не выполняется** (`HTTPClient::setURL()` отказывается),
  `Content-Length` обязателен, и `&` в URL недопустим — аргументы команды режутся по нему.

**Шесть топиков `wind/<id>/*`**, `<id>` = `SECRET_MQTT_STATION_ID` (сейчас `mast`):

| топик | кто пишет | QoS | retain | что несёт |
|---|---|---|---|---|
| `live` | станция | 0 | нет | `{"q":<счётчик>,"s":[4 скорости],"g":<порыв>}`, ~60 байт |
| `state` | станция | 1 | **да** | ровно объект `/api/data` плюс `sessionId` |
| `status` | станция | 1 | **да** | `{"online":true,"sessionId":…}`, и LWT `{"online":false}` |
| `hist` | станция | 1 | нет | `{"from":N,"a":[[t,min,avg,max],…]}`, до 15 минут за раз |
| `cmd` | оператор | 1 | нет | подписанная команда, см. ниже |
| `ack` | станция | 1 | нет | `{"id":…,"ok":…,"op":…,"detail":…}` на **каждую** команду |

Решения, которые в этой таблице не видны, а сломать их легко:

- **`q` — счётчик пакетов, а не метка времени.** Дашборд проигрывает пачку по своим
  50 мс и ему нужно знать лишь одно: не потерялся ли пакет. Метка стоила бы десяти байт
  в каждом кадре ради того, что приёмник и так знает
- **`live` не retained и QoS 0 намеренно.** Живой отсчёт, пришедший с опозданием, хуже
  не пришедшего вовсе, и ретрансмиссии здесь нечего спасать. По той же причине при
  обрыве хвост из накопленных отсчётов **выбрасывается**, а не копится: стрелка,
  которой скормили минуту протухших данных, показывает зрителю неправду
- **`state` и `status` retained, и это не симметрия ради красоты.** Зритель, открывший
  страницу через час, обязан увидеть текущую картину и узнать, что станция офлайн,
  а не ждать кадра, который не придёт
- **Быстрая половина — 5 Гц от внешнего питания и 1 Гц от батареи**
  (`CLOUD_LIVE_MS` / `CLOUD_LIVE_MS_BATTERY`), по четыре отсчёта в пакете.
  ⚠️ Сейчас всегда действует батарейный режим: внешнее питание не доходит до `IN+`
  TP4056 (задача 11), `powerSource` намертво `battery`, и **режим 5 Гц физически
  непроверяем**
- **Медленная половина — раз в 5 с, но немедленно (не чаще раза в секунду), если
  что-то в ней шевельнулось**: заряд, источник, процент батареи, светодиоды,
  `adcError`, аплинк, наличие часов. Флаг «шевельнулось» **липкий**: детектор
  самоочищается при каждом вызове, поэтому изменение, попавшее в секундный пол,
  иначе терялось бы навсегда — зарядка успевала бы смениться на «заряжено», а зритель
  до следующего тика видел бы старое
- **Минутные агрегаты — кольцо на 200 записей** (три с лишним часа), отдаются пачками
  по 15. Это то, что переживает обрыв: живые кадры выброшены, а что на самом деле
  было с ветром — здесь. Когда кольцо перетирает неотправленное, указатель
  «отправлено» подтягивается вперёд, иначе он гонялся бы за записями, которых нет

**Команды подписаны, и это главное.** TLS и логин на брокере ничего здесь не решают:
второй конец топика — чужая инфраструктура. Доверие даёт подпись, которую станция
проверяет сама, кто бы и как её ни доставил:

```
sig = HMAC-SHA256(SECRET_CMD_HMAC_KEY, id "\n" op "\n" args "\n" exp "\n" sessionId)
```

- **`sessionId` входит в подписываемое, но по проводу не идёт** — станция подставляет
  свой. Это и закрывает дыру, которую счётчик `id` закрыть не может: прошивка не пишет
  NVS и RTC нет, после перезагрузки `lastId` снова 0, и вчерашний перехваченный пакет
  прошёл бы. Нонс перевыпускается на каждую загрузку, так что такой пакет проваливает
  уже проверку подписи. `id` остаётся защитой **внутри** сессии, не между перезагрузками
- Кто подписывает — обязан повторить строку байт в байт: `id` и `exp` — десятичные без
  дополнения, `args` — сырая строка (пустая, если аргументов нет), разделитель — один
  `\n`, ключ — `SECRET_CMD_HMAC_KEY`, **раскодированный из hex в 32 байта**
- `exp` — абсолютный UNIX-срок, не длительность. Дальше 15 минут вперёд не принимается,
  и без синхронных часов не принимается ничего вовсе: судить о сроке нечем, а
  «принимать, пока часы не пришли» — это принимать вечно
- **Белый список операций, и он весь тут**: `gust-reset`, `zero-set`, `led`, `reboot`,
  `ota` (`url=` + `sha256=`, см. выше). Ценность закрытого списка в том, что прочитать его достаточно,
  чтобы знать, что может сделать украденный ключ. Никакого «выполни запрос» тут нет
  и не будет
- **Ответ уходит на всё** — в том числе на отказ. Именно в отказе оператору и нужно
  услышать причину; молчание неотличимо от мёртвого канала
- Команды исполняются в `loop()`, а не на задаче MQTT: они трогают состояние, которым
  владеет `loop()`, и залезать в него с другого ядра — это гонка, которая проявляется
  только невозможным показанием
- Перезагрузка по команде отложена на 1.5 с (ack надо дать уехать) и стоит **первой**
  в `serviceCloud()`, а не последней: подтверждённая перезагрузка обязана случиться,
  даже если связь умерла внутри этой паузы. И перед ней модем выводится из CMUX —
  ту же вежливость, что и OTA, иначе аплинк не переживёт собственный ресет

**Задержка ~1 с — это очередь, а не сеть, и она измерена** (2026-09-12). Публикация идёт
через `esp_mqtt_client_enqueue()`, а задача MQTT сидит в опросе сокета и разгребает outbox
только проснувшись. Полный круг команды: медиана **1162 мс**, но **442 мс**, если через
250 мс вдогонку послать ещё одно сообщение и разбудить задачу досрочно — значит настоящий
путь ~200 мс, а остальное очередь. По 4G медиана 1819 мс, по WiFi 1140 мс. Лечить нечем:
`esp_mqtt_client_publish()` по своей же документации «might block for several seconds»,
и блокировал бы он `loop()`, то есть 50-герцовый опрос датчика. **Оставлено как есть
осознанно.** Важное следствие для дашборда: запаздывание **постоянное, а не рваное**
(кадры 1 Гц приходят с медианой 1005 мс), но на 5 Гц ждать надо **пачку из пяти кадров
за один цикл опроса**, а не пять равномерных — буфер воспроизведения не имеет права
считать кадры равномерными.

**Учётки и права.** Три штуки, у всех фильтр `wind/mast/#`: станция (пишет всё, читает
`cmd`), зритель (только чтение), оператор (плюс запись в `cmd`). Разбор ACL и грабли
HiveMQ — в `tasks/10`. Учётка зрителя лежит в `wind-ui/.env` как `VITE_MQTT_VIEWER_*`,
потому что нужна сборке фронтенда; она **по построению** попадает в публичный бандл,
и потому это учётка, которая умеет только смотреть.

**Топик `state` публичен — со всеми последствиями.** Он retained, его содержимое это
ровно `buildDataJson()`, а читает его учётка, лежащая открытым текстом в публичном
бандле. Значит всё, что попадает в `/api/data`, автоматически становится публичным.
Отсюда округление координат до трёх знаков (см. §Контракт HTTP API) и отсюда же правило:
**новое поле в `buildDataJson()` — это публикация, а не диагностика.** Прежде чем
добавлять, проверить, что его не жалко отдать в интернет; если жалко — ему место
в `/api/site` или в отдельном эндпоинте, который отвечает только в своей сети.

**Клиент дашборда написан свой** (`wind-cloud-mqtt.js`, MQTT 3.1.1 поверх `WebSocket`),
а не взят из npm. Зритель только читает, а подписка на QoS 0 понижает доставку всего,
включая retained, опубликованные с QoS 1, — значит PUBACK/PUBREC/PUBREL и аллокатор
packet id не нужны вовсе. Зависимостей ноль, ~4.3 КБ gzip. Две ловушки, стоившие бы
дня отладки: границы WebSocket-сообщений **никак не связаны** с границами MQTT-пакетов
(нужен накопительный буфер с циклом разбора), а отказ в подписке у HiveMQ **тихий** —
SUBACK `0x80` при живом соединении, и выглядит это как «станция просто молчит».

**Три слоя изоляции облачного чанка**, и у каждого своя дыра, поэтому нужны все три:

1. **детерминированное имя чанка** в `wind-ui/vite.config.js` — без него имя это свойство
   текущего графа модулей, а не гарантия;
2. **фильтр в `gen_web_header.py`** (`SKIP_PREFIXES`), и обязательно с проверкой в обратную
   сторону: если под фильтр не попал ни один файл — падать. Молча промахнувшийся фильтр
   и есть тот самый регресс. Сам по себе код-сплит не спасает ни от чего: генератор берёт
   `wind-ui/dist` **рекурсивно целиком** и фильтрует только по расширению, поэтому любой
   новый чанк уезжает во флеш автоматически;
3. **`esp32_wind_station/check_web_header.py`** — сторож по уже закоммиченному заголовку.
   Смотрит на результат, а не на процесс: во флеш уходит не то, что генератор собрал
   сегодня, а то, что лежит в git. ⚠️ **Grep по `web_content.h` для содержимого бесполезен** —
   gzip развёрнут в десятичные байты, текста в файле нет вовсе, поэтому сторож распаковывает.
   Проверяет и массивы, на которые не ссылается ни один маршрут: такой ресурс прошивка
   никому не отдаст, но его байты всё равно уезжают в публичный коммит.

⛔ **Отдельная дыра — `WIND_SINGLE=1`.** Эта сборка включает `inlineDynamicImports`, то есть
склеила бы облачный чанк обратно в entry, и пароль зрителя уехал бы в артефакт claude.ai
открытым текстом — другой канал, другая аудитория, отозвать нельзя. Лечится **выбрасыванием,
а не инлайном**: условный `resolve.alias` на заглушку плюс `define: { __WIND_CLOUD__ }`,
который делает `import()` мёртвым кодом.

⛔ **`import.meta.env.VITE_*` подставляется литералом в том модуле, где написан.** Одна
строка `!!import.meta.env.VITE_MQTT_VIEWER_URL` в `wind-dashboard.jsx` увезла бы URL и логин
в entry-чанк, то есть в прошивку, **при полностью рабочем фильтре чанков**. Это самый
вероятный будущий регресс, и проверяется он одной командой: `import.meta.env` не должен
встречаться нигде, кроме `wind-cloud*`.

### Карта GPIO (прошивка ↔ документ сборки ↔ железо)

Таблица распиновки в `wind-station-assembly.md` обязана совпадать с макросами `PIN_*`.

**Плата с 2026-09-06 — ESP32 DevKitC, 38 pin, модуль ESP32-WROOM-32U** (было 30-pin DOIT
DevKit V1). Прошивку это не затронуло **ни одним пином**: набор 38-pin — надмножество
30-pin, все `PIN_*` на месте с той же функцией, и FQBN смена платы тоже не трогала
(суффикс `PartitionScheme=min_spiffs` появился позже и по другой причине — см. §Команды).
Переделана только медь
на макетке — схема **v8** (`wiring-v8.html`, генераторы `images/gen_wiring_v8_svg.py`
и `images/build_wiring_v8.py`). С 2026-09-13 рядом лежит **`wiring-v9.html`** —
это **целевая** схема задачи 11 (клавиша KCD4 на два полюса, десять плюсовых цепей
своими цветами, питание платы справа через мост `31↔32`), а не то, как собрано сейчас;
железо по ней ещё не переделано. Пять вещей, которые из этого следуют и которые легко забыть:

- ⛔ **шесть отверстий у левого края — ноги SPI-флеша, и запрет несимметричный.**
  На 38-pin выведен сам кристалл флеша: **сверху кол. 2·3·4 (`CMD·D3·D2`), снизу
  кол. 1·2·3 (`CLK·D0·D1`)** — и только они. Ранняя формулировка «колонки 1–4 держать
  пустыми» буквально неверна и мешает собрать плату: `1a` — это **`5V`**, туда перемычка
  в «+» рельс идти обязана, а `6a` — `GND`. Считать надо по буквам шелкографии, а не
  по номеру колонки: у верхнего и нижнего рядов они смещены на одну колонку.
  Перемычка (и даже просто пружина отверстия) на любой из шести — и плата либо не грузится
  молча, либо грузится через раз: ёмкость срывает чтение флеша на 80 МГц, при этом
  медленная `verify-flash` от esptool проходит успешно и «доказывает», что образ цел.
  Симптомы в Serial: `load:0xd0012000,len:4140`, длина вида `len:2113507310`,
  `rst:0x7 (TG0WDT_SYS_RESET)`, `partition 0 invalid magic number 0x0`, `Failed to set QIE bit`,
  и паники в случайных местах (`trc_set_per_pkt_rate`, `MDNS.addService`) с крошечным
  `EXCVADDR` — это битые страницы кода, а не баг в прошивке.
  ⚠️ **Правило априорное — экспериментом оно НЕ подтверждено.** Отказы, которые раньше
  числились здесь подтверждением, разобраны 2026-09-10/11 и объяснялись **бракованным
  модулем** `d4:e9:f4:04:0a:00`, а не медью макетки: другая плата в ТЕХ ЖЕ отверстиях
  отстояла 492 и 549 с без единого ресета, тогда как бракованная падала и **без единой
  перемычки**, и после полного стирания с побайтно проверенной перезаливкой, и уже будучи
  прошитой на `40m` — то есть со снятой ёмкостной проблемой. Правило оставлено в силе как
  разумная предосторожность: ноги флеша на 38-pin действительно выведены наружу. Но
  ссылаться на него как на объяснение конкретного отказа нельзя, пока плату не сравнили
  с заведомо исправной в тех же отверстиях — этот шаг стоит делать первым, он дешевле
  любой другой проверки.
  Разбор с картинкой и порядком действий — **`wiring-v8-3.html`** (генераторы
  `images/gen_next_v8_svg.py` и `images/build_next_v8.py`, блок `bb.flash_zoom()`).
  На 30-pin этих контактов не было, ловушка новая
- ⚠️ **флеш держим на `--flash-freq 40m`, и это осознанный запас, а не временный костыль
  на откат.** Повод, по которому частоту снизили, оказался ложным (см. пункт выше), но
  возвращать 80 МГц всё равно не надо. Цена: полоса шины падает с ~20 до ~10 МБ/с в режиме
  DIO, промах кэша инструкций дорожает вдвое — на этой станции незаметно, потому что вся
  нагрузка (50 Гц АЦП, SSE 20 Гц, отдача gzip-блоба) упирается в радио и lwIP, а не во
  флеш. Выгода: двойной запас по таймингам шины — на макетке, в поле, на морозе, от
  батареи. Решает асимметрия последствий: у «40 МГц оказалось мало» симптомов не бывает
  вовсе, а у «80 МГц оказалось мало» они выглядят как `partition invalid magic`,
  `TG0WDT_SYS_RESET` и паники в случайных местах — то есть сутки отладки на ровном месте.
  Частота лежит в заголовке образа по `0x1000` (байт 3, младший полубайт: `0` = 40 МГц,
  `f` = 80 МГц), и **OTA этот заголовок не переписывает** — настройка переживает любое
  число заливок по воздуху, сменить её можно только по USB (адреса `0x1000`/`0x8000`/
  `0xe000`/`0x10000`, команда целиком — в `wiring-v8-3.html`). Проверить, что реально
  лежит на чипе: `esptool --before no-reset read-flash 0x1000 4 header.bin`.
  ✅ **Вычитано с чипа 2026-09-11: `e9 03 02 20`** — magic `0xe9`, режим DIO, 4 МБ,
  младший полубайт байта 3 равен `0`, то есть 40 МГц подтверждены самой микросхемой,
  а не выводом esptool. Прежняя оговорка «залито командой с 40m, но с чипа не читали» снята
- **у ESP-32U нет печатной антенны**, только u.FL: без пигтейла плата почти не передаёт.
  Взамен антенна выносится за стенку глухого IP65-бокса и разносится с LTE-антенной модема.
  С историей «ноутбук заходит, телефон никогда» это не связано — та про WPA3/PMF, см. §Сеть
- **мост USB теперь CP2102** (`VID_10C4&PID_EA60`) вместо CH340C (`VID_1A86&PID_7523`):
  другой драйвер, другой номер COM-порта, оговорка про 460800 больше не действует
- **рельсы этой макетки короче банка на две колонки с каждой стороны** — полосы «+»/«−»
  идут от кол.3 до кол.61, а ряды a…j от 1 до 63. Плата села от самой первой колонки,
  поэтому над её «5V» отверстия рельса нет: перемычка идёт **по диагонали** в кол.3.
  То же на правом краю — Boost#1 IN− из `62a` наискосок в кол.61. Полурельс — одна цепь,
  так что диагональ меняет только длину провода

- **Аналоговые входы (только ADC1)**: GPIO34 = скорость, GPIO35 = направление (не подключён,
  см. `HAS_DIRECTION`), GPIO32 = напряжение батареи
- **Светодиоды**: GPIO17 = зелёный (батарея >60%), GPIO16 = жёлтый (ветер >5 м/с ИЛИ батарея
  30–60%), GPIO4 = красный (ветер >15 м/с ИЛИ батарея 10–30%, мигает при <10%),
  GPIO5 = WiFi (**горит, когда станция кому-то доступна — есть клиент на точке ИЛИ живой
  аплинк; мигает, только когда ни того ни другого**), GPIO18 = ошибка. Зелёных ламп две,
  и их путают: ровный свет GPIO5 — это сеть, а не заряд. Схема v4 перенесла светодиоды на нижний
  ряд пинов, резисторы 220 Ω теперь на плате; было 26/27/14/25/33. На 38-pin эти пять пинов
  сидят в **колонках 7–11** (на 30-pin были 5–9), а сами резисторы уехали в полосу 22–36
  с шагом 3 колонки
- **UART модема 4G/GPS** (`HAS_MODEM 1`): **GPIO27 = TX** → кол. 37 макетки (буква `R`,
  RXD модема), **GPIO25 = RX** ← кол. 38 (буква `T`, TXD). Буквы через линк намеренно не
  совпадают. Это **третий расклад для одной и той же пары проводов**, и каждый раз
  выигрывала медь, а не рисунок: v6 рисовалась под 27/26, на 30-pin косичка по факту легла
  на 26/25, на 38-pin (схема v8) — на 27/25. Отсюда следствие, которое легко потерять:
  **свободным стал GPIO26, и он лежит ровно МЕЖДУ двумя проводами** — втыкать в него
  нельзя ничего, иначе пара разъедется снова. Затвор P-FET остаётся на **GPIO33**,
  и с 2026-09-11 это **не «когда-нибудь», а условие работы 4G**: после перезагрузки
  ESP32 модем остаётся в CMUX и на голый `AT` отвечает полной тишиной, а снять CMUX
  нечем — PWRKEY притянут к земле через R104, выход из CMUX у A7670 сломан по прошивке.
  Закрыть это программно удаётся ровно там, где перезагрузка идёт **через код**:
  `ArduinoOTA.onStart()` выводит модем из CMUX штатно, и OTA аплинк больше не убивает
  (проверено дважды — канал вернулся с первой попытки за ~2 с и с тем же PPP-адресом,
  то есть PDP-контекст даже не разрывался). А паника, brownout и сторожевой таймер
  не доходят ни до какого кода — для них лекарство только одно, снять питание.
  Разбор — `tasks/10-a7670e-4g-gps.md`.
  Оба пина — ADC2, и это допустимо (UART, не аналоговое чтение). Главное:
  **`Serial2` по умолчанию сидит на GPIO16/17 — это жёлтый и зелёный светодиоды**,
  поэтому пины передаются в `Serial2.begin()` явно, порядок аргументов `(rx, tx)` —
  `Serial2.begin(115200, SERIAL_8N1, 25, 27)`
- **Дисплей** (`HAS_DISPLAY_LINK 1`): **GPIO23 = UART1 TX**, макетка `18j`, только
  передача. Ради него **PPP переехал с UART1 на UART2** (`MODEM_PPP_UART`, 2026-09-26):
  библиотека PPP по умолчанию берёт UART1, а `Serial2`-консоль модема и PPP и так
  никогда не держат порт одновременно (`Serial2.end()` перед `PPP.begin()`). ⚠️ Второе
  следствие, о котором легко забыть: `Serial1.begin()` **без явных пинов** садится на
  умолчания ядра RX1=26 / TX1=27 — а GPIO27 это провод к RXD модема. Пины передавать всегда.
  Кадр пишется, только если целиком влезает в кольцо, иначе считается в `dispDrop`
  строки телеметрии — `loop()` не блокируется
- **Статус TP4056**, открытый сток, `INPUT_PULLUP`, активный уровень LOW: GPIO13 = CHRG,
  GPIO19 = STDBY. Выбраны потому, что ни один не strapping — линия с открытым стоком,
  прижатая к земле в момент включения на GPIO0/2/12/15, поменяла бы режим загрузки
- GPIO4 — пин ADC2, используется как обычный цифровой выход: это можно, конфликт ADC2/WiFi
  касается только аналогового чтения. GPIO5 — strapping: светодиод на землю через 220 Ω
  лишь коротко мигнёт при включении

**Никогда не переносить аналоговые входы на ADC2 (GPIO 0, 2, 4, 12–15, 25–27)** — ADC2
недоступен, пока работает радио.

### Математика сигнала завязана на номиналы резисторов

Константы прошивки и номиналы в BOM обязаны совпадать.

- Делитель датчика: **10 кΩ + 5 кΩ последовательно (= 15 кΩ) сверху + 10 кΩ снизу** →
  `Vsensor = Vadc × 2.5` (`SIGNAL_DIVIDER_RATIO`). В наборе нет 15 кΩ, поэтому верхнее плечо
  собрано из двух; отношение то же. Почему не наоборот: АЦП ESP32 на 11 dB линеен только
  150 мВ … 2.45 В, а большее плечо снизу дало бы 3.0 В на полной шкале и занижало бы
  скорости выше 49 м/с на 5–15%
- Делитель батареи: 100 кΩ + 100 кΩ → `Vbat = Vadc × 2.0` (`BATTERY_DIVIDER_RATIO`).
  Тапится провод холдера, а не TP_B+: TP4056 подпитывает TP_B+ от USB и подделывает батарею
- Датчик **новый**: 0–30 м/с, только скорость. `SPEED_MAX = 30.0` — оставленные там 60
  от старого датчика удваивают каждое показание. `HAS_DIRECTION 0`, GPIO35 висит в воздухе
- Питание: диодное ИЛИ на **двух 1N5819** + **двух Mini Boost** (HW-085/TMF002 на MT3608;
  №1 = 12 В для датчика, №2 = 5 В от батареи). Шина ~4.7 В независимо от источника.
  Второй буст нужен потому, что падение на AMS1117 — 0.8–1.25 В, а не 0.3 В: без него
  один диод от батареи оставил бы шину на 3.4 В и ESP32 ловил бы brownout на передаче

Смена физических резисторов без правки константы даёт молча неверные показания. В одной из
прошлых версий баг вида `(raw/4095) × 1.515 × 60` завышал скорость в 1.5 раза — при правке
математики АЦП сохранять `analogReadMilliVolts()` (применяет калибровку из eFuse), а не
сырой `analogRead()`.

### Порог АЦП — это гейт, а не смещение

`SPEED_ZERO_MV = 150.0` работает как ворота: на пороге и ниже — штиль и ноль, выше —
откалиброванные милливольты уже и есть сигнал. **Вычитать его нельзя.** Вычитание (так код
делал до 2026-08-08) сдвигало всю шкалу вниз на целый пол: при 66.7 мВ на м/с это 2.2 м/с
ошибки в каждом отсчёте, настоящие 3 м/с превращались в 0.8. Симптом — станция выглядит
мёртвой, пока чашки не раскрутишь сильно.

Следствие, которое фиксом не лечится: скорости ниже ~2.3 м/с всё равно дают 0, и показание
прыгает с нуля сразу к ~2.3. Внизу нечего интерпретировать — прошивка может лишь перестать
портить остальную шкалу. Границу двигает только железо: `HAS_LEVEL_SHIFT 1` плюс резистор
47 кΩ с 3V3 на узел делителя. **Флаг включать только когда резистор впаян**, иначе показания
уедут вниз примерно на 6 м/с. Ноль после этого калибруется на месте через `/api/zero`.

переписанные хеши никого не задели. Теперь так больше нельзя: после публикации такой проход
стоит force-push, сломанные клоны и — главное — уже не убирает ничего, что успели прочитать
или проиндексировать. **Секрет, попавший в публичный коммит, надо считать сгоревшим и менять.**

- проход 1 — пароли домашних WiFi-сетей
- проход 2 — точные координаты, IMEI и SN модема, имена домашних сетей; заодно `--blob-callback`
  подменил два снимка модуля на версии с закрашенной наклейкой
- проход 3 — плейнтекст старых паролей точки и OTA

После третьего прохода полный скан базы объектов (`git cat-file --batch-all-objects`)
не находит ни одной из этих строк ни в одном блобе. Остатки старых паролей внутри
gzip в `web_content.h` и внутри `WindStation-kit.zip` подстановкой не берутся — но они
и не важны: пароли **сменены**, старые не подходят ни к чему.

**Правило для публичного репозитория.** Ничего из перечисленного не должно появляться
ни в коде, ни в документации, ни в логах, которые копируются в `tasks/`:

- **координаты мачты** — полная точность это домашний адрес. В `secrets.h`
  (`SECRET_STATION_LAT`/`LON`/`ALT_M`), в документах — округление до трёх знаков (~100 м)
- **любые пароли** — только имя макроса из `secrets.h`, никогда значение. Пароли точки
  и OTA сменены перед публикацией: старые остались в истории внутри gzip `web_content.h`
  и `WindStation-kit.zip`, вычистить их оттуда нельзя — смена и была фиксом
- **имена домашних сетей** — в примерах `HomeSSID`, `HomeSSID-2`. Не пароли, но SSID
  геолоцируются по публичным базам вроде WiGLE
- **IMEI / SN / ICCID модема, номер SIM** — при вставке AT-логов в `tasks/` заменять на
  `<IMEI>`, `<SN>`. APN и имя оператора не секрет, выданный CGNAT-адрес тоже

Отслеживается ~220 файлов (16 МБ). `.gitignore` держит вне истории всё пересобираемое:
каталоги сборки (`build/`, `esp32_wind_station/build/`, `node_modules/`, `wind-ui/dist/`),
снапшоты `esp32_wind_station.zip` и `wind-ui.zip`, черновики `*.bak-*`, `temp/`, `tmp/`, логи,
служебные файлы KiCad (`*.kicad_prl`, `*.lck`, `.history/` — внутри неё свой `.git`) и `.idea/`.
Два исключения, которые выглядят нелогично, но сделаны намеренно:

- `esp32_wind_station/web_content.h` **коммитится**, хотя генерируется: без него прошивка
  не собирается на машине без установленного `node_modules`
- `WindStation-kit.zip` **коммитится**, хотя это архив: `tools/*.ps1`, `SETUP.md` и
  `НАЧНИ-ОТСЮДА.txt` существуют только внутри него, в рабочем дереве их нет
- `drivers/A7600X-Windows-Driver.7z` (10.8 МБ) **коммитится**, хотя это чужой бинарник:
  живой источник один — GitHub стороннего человека, официальная страница Waveshare
  отдаёт 403 автозагрузчикам. Хеш записан в `A7670E-DRIVERS.md`. Распакованная
  `drivers/a7600x/` в историю не идёт

## Что чаще всего сбивает с толку

Полный разбор — в `FIRMWARE.md`, читать перед правкой `.ino`. Самое частое:

- Первые 30 секунд после старта батарея всегда читается как `absent` — `readBattery()`
  не вызывается в `setup()`. Нули в этот момент ничего не значат
- Питание по USB-разъёму ESP32 не доходит до TP4056, поэтому на столе плата честно рапортует
  `battery/absent` — это не баг
- В SSE-сокет писать только через `sseFlush()` (`lwip_send` + `MSG_DONTWAIT`). `sseClient.print()`
  при отстающем клиенте вешает `loop()` до 10 секунд, а вместе с ним и опрос датчика.
  `NetworkClient::setTimeout()` от этого не спасает, он вообще ни на что не влияет
- Детектор обрыва сигнала больше не ловит выдернутый провод: открытый вход читается тем же
  полом АЦП ~145 мВ, что и датчик на нуле. Видно только глухое замыкание на землю
- В строке Serial есть `loopMax`, `log` и `sseDrop` — по ним видно, тормозит ли `loop()`
  и не захлёбывается ли поток. `loopMax` больше нескольких мс = что-то блокирует.
  `log` (оно же `logMs` в `/api/data`) — это цена самой строки телеметрии на 115200,
  12–13 мс, и она из `loopMax` вычтена: пока их не разделили, `loopMax` показывал
  длину собственной диагностики
- Задержка облачных сообщений около секунды — это **outbox esp-mqtt**, а не связь
  (доказано: 1162 мс против 442 мс, если задачу разбудить входящим сообщением). Искать
  её в качестве 4G бесполезно; разбор — §Облачный канал

## Состояние проекта

Модуль на макетке, перфоплата и PCB отклонены осознанно. Раздел BOM в документе сборки —
источник истины по тому, что куплено, а что нет. Решения, уже отражённые в коде и документах:

- TP4056 + Schottky 1N5819 для разделения нагрузки (не YX-850)
- Делитель сигнала 10 кΩ снизу + 10 кΩ + 5 кΩ последовательно сверху (не 20 кΩ — старый
  номинал загонял АЦП в нелинейную зону)
- Мониторинг батареи на GPIO32 через делитель 100k/100k, тапится провод холдера
- Новый датчик 0–30 м/с без канала направления

## Соглашения при правке

- Три пласта движутся вместе. При смене пинов, API или математики — сразу править таблицу
  распиновки, BOM и диагностику в `wind-station-assembly.md` и поля дашборда, если изменилась
  форма API
- Документ сборки использует диаграммы Mermaid для потока питания и раскладки в корпусе —
  держать их согласованными с BOM
- Разделы про безопасность (обращение с батареей, проверка пресетов буста, предупреждения
  о полярности) несущие — не сокращать ради краткости
- Гайды по сборке генерируются из `images/bb_lib.py`, а не рисуются руками:
  `gen_*.py` → SVG, `build_*.py` → HTML. См. `images/BREADBOARD-STANDARD.md`
- `.ino` — комментарии и `Serial.print` по-английски, отступ 2 пробела, `#define` для пинов
  и флагов в SCREAMING_SNAKE, `const float` для калибровок, глобалы и функции camelCase,
  секции вида `// ===== PINS =====`. Плотность комментариев высокая: у каждой константы
  объяснение, какую физическую проблему она решает — держать этот уровень
- Python и вся документация — по-русски
- `wind-ui` — JSX, одинарные кавычки, без точек с запятой, отступ 2 пробела
