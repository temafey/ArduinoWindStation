# Стандарт блоков «вид макетки» (Fritzing-подобные SVG-гайды)

Единый визуальный стандарт для пошаговых гайдов сборки метеостанции.
**Источник истины в коде — `images/bb_lib.py`** (генераторы блоков). Этот файл — человекочитаемое описание.
**Эталон, из которого выведен стандарт** — `images/breadboard_sample_current.svg` (ESP32 DOIT V1 30-pin, задачи 01–03).

Гайды генерируются, НЕ пишутся руками:
```
python images/gen_step04_svg.py   # → images/step04_power_rail.svg
python images/gen_step05_svg.py   # → images/step05_battery_divider.svg
```
Интерактивный HTML собирают билдеры в scratchpad (`build_step04.py`, `build_step05.py`):
SVG + hotspot-слой + карточки деталей + модалка с фото (base64) + шаги + заметки.
Общие CSS/JS — `_std_css.txt` / `_std_script.txt`.

Проверка рендера обязательна: `rsvg-convert` (`C:/msys64/mingw64/bin`) и headless Chrome для HTML.

## 1. Геометрия макетки (общая, неизменная)

- **Колонка N → x = 88 + (N−1)·17** (шаг 17 px). Напр. кол.22 = 445, кол.46 = 853.
- **Верхний банк (ряды a–e):** y отверстий 298, 316, 334, 352, 370.
- **Нижний банк (ряды f–j):** y отверстий 406, 424, 442, 460, 478.
- **Плата:** rect x=74 y=232 w=1004 h=298 rx=12, fill `#f4f0e6`, stroke `#d8d2c0`.
- **Рельсы:** верх +@242 / −@270; низ — параметр (`bottom="+-"` для 04/05: +@498/−@526; `"-+"` для эталона).
- **Полосы отверстий** рельсов: тёплая `#c9a9a0` (у «+»), холодная `#a0aac9` (у «−»).
- **Разрыв 830-макетки** посередине (rect `#e9e3d3` @380) — в 04/05 показываются 4 перемычки-моста.
- Метки рядов a–j @x=66; номера колонок (20,25,…55) @y=286.

### 2a. Десять плюсовых цепей (схема v9 и далее)

Начиная с v9 «красный провод» перестал что-либо значить: на плате с диодным ИЛИ, тремя
бустами и двухполюсным выключателем плюсовых цепей одиннадцать, и половина под разным
напряжением. Каждая получает свой цвет и номер `P1…P10`; номер дублируется в списке
соединений (поле `circ` в `WIRES`). Канонический `bb.PLUS` закреплён за **P8** — это «+»
LOAD, тот самый цвет, которым шина рисовалась во всех прошлых версиях.

| № | Цепь | Напряжение | Цвет | Почему такой |
|---|---|---|---|---|
| P1 | +5 В адаптера | 5.0 В | `#ff7043` коралловый | тёплый, но явно не красный: вход, а не шина |
| P2 | «+» пакета через F1 | 3.0–4.2 В | `#7d1128` тёмная вишня | «батарейный» тёмный тон, пара к BATT− `#8e44ad` |
| P3 | отвод холдера на делитель | 3.0–4.2 В | `#6d4c41` коричневый | тот же уровень, что P2, но отдельный провод |
| P4 | OUT+ TP4056 — **до** полюса A | 3.0–4.2 В | `#c25e00` жжёный оранжевый | пара к P5, различать обязательно |
| P5 | кол.51 — **после** полюса A | 3.0–4.2 В / 0 | `#a97400` охра | пара к P4: темнее и желтее |
| P6 | выход Boost#2 | 5.14 В | `#6b8e23` оливковый | единственная «зелёная» силовая — не путается ни с чем |
| P7 | узел ШИНА — **до** полюса B | ~4.7 В | `#00838f` тёмная бирюза | пара к P8: холодный против канонического красного |
| P8 | «+» LOAD — **после** полюса B | ~4.7 В / 0 | `#d23b2e` = `bb.PLUS` | канон: это и есть шина питания платы |
| P9 | 12 В на датчик | 12.0 В | `#c2185b` малиновый | уходит за край, рядом только TX `#e0218a` (далеко по холсту) |
| P10 | 5.2 В на модем | 5.2 В | `#ff8f00` янтарный | рядом только жёлтый LED (далеко по холсту) |

Пары `P4/P5` и `P7/P8` — самые важные: именно они показывают, что выключатель реально
рвёт. Ни один из десяти не совпадает с занятыми ролями: GND `#1a1a1a`, SIG `#6aa9e0`,
BATT− `#8e44ad`, датчик `#0e9488`, TX `#e0218a`, RX `#3949ab`, CHRG `#2a7de1`,
STDBY `#a68bff`, пунктир плана `#b08a2a`.

Легенда рисуется блоком **`plus_legend(x, y, w, items, title, row_h, head_h)`** —
образец цвета, номер, имя, напряжение и маршрут одной строкой.

## 3. Блоки (все — функции `bb_lib`)

- **`esp32(subtitle, highlight, adc_callout)`** — DOIT DevKit V1, 30 пинов, ОБА ряда.
  Корпус x=80..342, y=316..476. USB-C слева.
  **Верхний ряд (y=311), слева→направо:** VIN GND 13 12 14 27 26 25 33 32 35 34 VN VP EN — цвет по роли.
  **Нижний ряд (y=471):** 3V3 15 2 0 4 16 17 5 18 19 21 RX TX 22 23 — все жёлтые.
  Центр пина верх: `x = 88 + 17·k`; напр. VIN=88, GND=105, GPIO26=190, GPIO32=241, GPIO34=275.
  `highlight=["32"]` рисует оранжевое кольцо вокруг активного пина этой задачи.
  Провода к пинам подключаются в точке (центр пина, y=311) — дуги над платой, как LED-провода эталона.
- **`resistor(col_l,col_r,row,bands,label)`** — тело `#d9c79c`, ножки `#9a8f6a`, тонкие полосы `bands`.
  100k (5 полос) = коричн-чёрн-чёрн-оранж-коричн `["#7a4a12","#1a1a1a","#1a1a1a","#e8873a","#7a4a12"]`.
- **`led(cx,color,stroke,gpio,sub,muted)`** — кружок r=9, ножки, «+» у анода, GPIO-подпись снизу.
- **`cap_ceramic(col_l,col_r,row,label)`** — «леденец» с «104». **`cap_electrolytic(col_p,col_m,row,label)`** — полярный, +/−.
- **`diode_schottky(col_l,col_r,row,label,cathode)`** — корпус `#2b2b2b`, светлая полоса-катод.
- **`ptc(col_l,col_r,row,label,muted)`** — жёлтый овал «PTC».
- **Реалистичные модули (как ESP32, а не пустые коробки):**
  - **`mod_tp4056(x,y,w,h,pins,usb_cx)`** — чёрный текстолит `#17181c`. Пады на ВЕРХНЕЙ кромке; разъём **Type-C — ПО ЦЕНТРУ (usb_cx, снизу)** как разделитель между входом (IN±, слева) и группой батарея/выход (OUT−,B−,B+,OUT+, справа). LED CHG/STBY, IC «4056», чип DW01/8205. `pins`=[(px,label,color)×6] с зазором посередине под usb_cx.
  - **`mod_boost(x,y,w,h,pins)`** — чёрная плата MT3608: пады сверху, **ВХОД (IN±) слева, ВЫХОД (OUT±) справа**, экранированный дроссель «3R3» по центру как разделитель, IC, перемычки A/B у выхода. `pins`: первые 2 = вход, последние 2 = выход.
  - **`mod_usb_c(x,y,w,h,pins)`** — светлая карточка, круглый панельный разъём с USB-C-слотом, красно-чёрный пигтейл от падов (пады сверху).
  - **`switch_rocker(x,y,w,h,terminals)`** — красный клавишный выключатель (O/I) в чёрной рамке, terminals=(tx,ty,label) на левой кромке.
  - Пады: `_pad(px,py,label,color,side)` (side=top|left|right); `_pads_top(pins,y)` для верхней кромки. **Все пады модулей — на ВЕРХНЕЙ кромке**, провода подходят сверху (иначе провод прячется под телом модуля — модуль рисуется поверх проводов). Вход и выход разделяются центральным элементом (USB-C / дроссель). GND-пад на тёмной плате — `PAD_GNDp` (иначе не виден).
- **`module_box(...)`** — устаревшая обобщённая «коробка»; для настоящих модулей использовать функции выше.
- **`battery_pack(x,y,…,minus_net_color,minus_label)`** — 2 холдера-пилюли, шины «+»/«−». Для BATT− передавать `minus_net_color=PURPLE`.
- **Блоки 38-pin платы** (со схемы v8):
  - **`esp32_38(subtitle,highlight,adc_callout,usb_label,title,antenna)`** — ESP32 DevKitC,
    19 колонок вместо 15, u.FL вместо печатной антенны. `PIN_TOP38`/`PIN_BOT38` — имя пина → x.
  - **`flash_warn(cols_top,cols_bot,label)`** — пунктирные рамки вокруг шести контактов
    SPI-флеша прямо на схеме сборки.
  - **`flash_zoom(x,y,cell,hole,title,sub)`** — те же шесть контактов КРУПНО, отдельным
    блоком: колонки 1–6 обоих банков, капсула = пять отверстий колонки = одна точка.
    Нужен потому, что «колонки 1–4 держать пустыми» буквально неверно (в 1a стоит «5V»),
    а запрещены разные колонки в разных банках: сверху 2·3·4, снизу 1·2·3. Три статуса —
    `ZOOM_NO` (нельзя ничего), `ZOOM_OK` (занято делом), `ZOOM_FREE` (свободно).
- **Блоки схемы v9:**
  - **`switch_dpst(x,y,w,h,terminals,key_box,pairs,pole_labels,title,subtitle,link_note,
    title_x,title_anchor)`** — клавишный KCD4 на ДВА полюса: корпус, клавиша, четыре
    **ножевых контакта 6.3 мм** (`SPADE_W/SPADE_H`), скобки над парами одного полюса
    и подпись «клавиша одна — полюса ходят вместе». `terminals` = [(x, label), …] по
    порядку слева направо, `pairs` говорит, какие из них образуют полюс.
    `title_x`/`title_anchor` (добавлены в v9) сдвигают заголовок: по умолчанию он стоит
    по центру верхней кромки, но провода к контактам падают сверху вертикально и проходят
    ровно сквозь буквы. Двигать провода нельзя — контакт стоит под своей колонкой,
    поэтому двигается подпись, в пустую часть кромки. Параметры **аддитивные**:
    без них функция рисует ровно то же, что раньше.
  - **`hop_dpath(pts, hops, r=7)`** — путь по точкам `pts`, в котором на перечисленных
    местах `hops` = (x, y) или (x, y, r) провод делает дугу-мостик вместо пересечения.
    Нотации намеренно не похожи: **точка = соединение, дуга = провод просто лежит поверх**.
    Дуги ставятся на ГОРИЗОНТАЛЬНОМ проводе при пересечении провод↔провод и на
    ВЕРТИКАЛЬНОМ — при пересечении с рельсом.
  - **`hop(x,y,color,direction,r,w,bg,side,halo)`** — тот же мостик отдельной фигурой,
    когда путь рисуется не через `hop_dpath`.
  - **`plus_legend(x,y,w,items,title,row_h,head_h)`** — панель «Десять плюсовых цепей»:
    квадрат-образец, номер, имя, напряжение, маршрут. См. §2a.
- **`legend(items)`**, **`mm_point(x,y,label)`** (красн+чёрн щупы), **`breadboard(bottom)`**, **`defs(...)`**.

## 4. Правила

1. **Все блоки — только через `bb_lib`.** Новый компонент → сначала функция в `bb_lib`, потом использование.
2. **Провода и подписи-инструкции** пишутся в генераторе поверх блоков (дуги плавные, не прямоугольные).
3. **Активный пин задачи** — оранжевое кольцо + подпись в subtitle ESP32.
4. **Уже собранное** из прошлых задач — `opacity 0.3–0.4` (контекст).
5. **Точная распиновка**: провод к GPIO идёт в реальный пин ESP32 (по таблице §3), не в абстрактный вывод.
6. HTML-шаги: содержимое `<li>` оборачивать в один `<span>` (grid `30px 1fr` иначе рвёт текст по словам).
